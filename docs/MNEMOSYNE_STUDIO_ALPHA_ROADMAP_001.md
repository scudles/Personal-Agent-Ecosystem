## 2. 三条工程判断（我认为这几条决定后续返工量）

### 判断 1 · 先把"她说的话"定义清楚，再接她的嘴

**P1.0 必须早于 P1.2。**

ACP 一接，房间里会同时出现四种文字：用户打的、agent 说的、系统转发的、工具吐的。
**现在 schema 里没有 `authority` / `origin` / `caused_by`——这四种文字会以完全相同的形态入库。**

事后再拆表，要回填**已经在库里的历史数据**，而那些数据的来源信息**早就丢了**，只能靠猜。
**现在库里 0 条消息，是做这件事唯一免费的时刻。**

### 判断 2 · No Debt 必须是"会失败的测试"，否则只是一句口号

P0 之所以"符合 No Debt"，是因为它**还没实现这些能力**——不是因为它守住了。
一旦 P1 有人想加未读红点，目前**没有任何东西会报警**。

**做法**：`test/no-debt.test.mjs`，静态扫描 `src/` 与 `server/`，命中禁用词即失败：

| 类别 | 禁用词（示例） |
| --- | --- |
| 社交压力 | `unread` `unreadCount` `badge` `mentionCount` `pendingReply` `lastSeen` `lastActive` `presence` `typing` `streak` `catchUp` `sinceLastVisit` |

**这不是形式主义**——它是唯一能在加功能时**自动**变红的东西。词表可增，规则只有一条：**数人的，进来就红。**

> 一句要同时记住的话：**「通知」允许，「催」不允许。**

### 判断 3 · 真实库迁移要趁 0 条消息

002 是「无条件重建五张表」。**有数据之前迁移成本为零，有数据之后同一步就是风险操作。**
→ P1.0 收尾时把 `.data` 迁到最新并留三件套备份。

**备份必须三件套**：主库只有 4 KB，**111 KB 数据在 WAL 里**——只拷 `.sqlite` 会丢数据。

## 3. 各阶段：交付物 / 依赖 / 验收条件

### P1.0 · 数据地基

| 项 | 内容 |
| --- | --- |
| **交付物** | `migrations/003_p10.sql`（`authority` / `origin` / `caused_by` / `run_events`）；`test/provenance.test.mjs`；`test/no-debt.test.mjs`；`.data` 迁移完成记录 |
| **依赖** | DSH 补齐 F1/F2 两条测试（她交付的缺口） |
| **验收条件** | ① 迁移后 `.data` 的 `schema_migrations` 含 `003_p10`；② 插入 `authority='system'` 被拒（`CHECK` 或触发器）；③ `run_events` 存在且**不进 bootstrap 的 messages 列表**；④ 禁用词扫描 0 命中；⑤ **对 003 新增三条变异全部 CAUGHT**；⑥ 旧消息迁移后仍可 bootstrap 读到 |

### P1.1 · 成员与呈现

| 项 | 内容 |
| --- | --- |
| **交付物** | 头像/名字由 `member.display_name` + `member.kind` 驱动，删除字面量 `'F'` |
| **依赖** | P1.0 |
| **验收条件** | ① `grep "'F'"` 在 `src/` 无命中；② 两个 agent 成员渲染出不同名字与头像；③ 加第三个成员（observer）**不需要改前端代码** |

> **这一阶段的隐含验收：加成员不改代码。** 若做不到，说明成员信息还没真正从数据来。

### P1.2 · Hermes ACP 接入

| 项 | 内容 |
| --- | --- |
| **交付物** | `hermes acp` 子进程适配器（`RuntimePort` 实现）；token 落盘并绑定 peer；超时/崩溃隔离；失败时半句只进 `run_events` |
| **依赖** | P1.0（来源字段）+ P1.1（能分辨谁在说）+ **用户对"真实 prompt 一次"的单次授权** |
| **验收条件** | ① 杀子进程后房间仍可用、可继续发消息；② 失败 run 的 `messages` 只多一条（用户的）；③ 全库 `authority='system'` 行数 = 0；④ `run_events` 有 `partial_chars` 但 `messages` 无半句；⑤ 一次真实回复在页面上可读，且 `origin='runtime'`、`caused_by` 指向触发消息 |
| **不可自动化** | ⑤ 需要真实模型调用 → **费用 + 内容出站**，必须单独授权 |

### P1.3 · DSH ACP 自举（DSH 专项）

| 项 | 内容 |
| --- | --- |
| **交付物** | 判别脚本或命令 + transcript：`initialize` / `session/new` / `session/close`；**`session/prompt` 0 次** |
| **依赖** | 无 |
| **验收条件** | ① `initialize` 有响应（不是超时）；② `session/new` 返回 sessionId；③ 桌面上不关 DSH 时是否可行，**明确写出结论**；④ 若不可行，说明是"只能作为独占 Resident"还是"根本不通" |

**已知两个候选根因**（未判别）：
- H1 单实例/缓存锁：`Unable to move the cache: 拒绝访问 (0x5)`
- H2 profile 未加载插件：`profiles/acp/cordis.patch.yml` 内容是 `[]`

**判别方法**：`--profile <name> --patch <显式插入 dsh-acp 的文件>` 跑一次即可分流。**这个判别只有 DSH 自己能做**（要改她自己的 profile 与插件加载链）。
