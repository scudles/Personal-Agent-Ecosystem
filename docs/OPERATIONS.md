# 安装、启动与使用

## 运行环境

Windows 11 x64，系统 .NET Framework 4.x/WPF。自带 runtime/node.exe（Node 26.12.1，内置 SQLite），无需 npm install 或 .NET SDK。源码在 desktop，编译结果 runtime/native/TriReviewBridge.exe。Node 许可保留在 runtime。

## 启动与退出

1. 双击 D:\TriReviewBridge\启动原生工作台.cmd。
2. 启动器只启动本项目模拟后台，监听 127.0.0.1:48732；令牌从 data/workbench-config.json 读取，不进入URL或日志。
3. 关闭窗口只关闭该窗口；其他窗口和后台继续工作。最小化使用 Windows 标准控件。
4. “停止后台”需要明确确认，排空正在执行的模拟操作后关闭。不会停止原生 Agent 应用或凪。

## 项目与会话

左侧自由创建、命名、归档项目和 Workspace。不存在不可逆删除入口。项目设置可填写说明并登记成员权限。本机用户是当前已认证的用户；受限模拟 Agent 测试凭证具备项目/会话范围，不提供远程登录或通用多用户身份发行。

新空间默认暂停，参与者未绑定。点击“绑定模拟会话”逐一选择，随后可恢复该模拟空间。原来的 Nagi 历史空间冻结，三个真实绑定不能替换或恢复。

“另开原生窗口”打开同一个后台、同一份会话历史的另一个 WPF 进程；各窗口可自行选择项目与会话，不复制历史。当前接收对象按 Workspace 持久化，因此同一个 Workspace 在多个窗口中共享该设置；不同 Workspace 互不影响。

## 定向消息

用上方选择器选择一个或多个接收方。正文、代码、引用和历史中的 @ 不改变路由；未选择对象禁止发送。多个对象分别收到原材料，不自动收到彼此意见。

选择 Agent 消息点回复，默认选中作者，可手动改变；引用只附该条内容，不附整个历史。转交保存原消息ID、作者、项目、空间、转交者和理由；跨项目必须明确确认。

普通正文按原文展示。哈希、nonce、原协议和来源证据在技术详情中。状态刷新不等同于模型逐字流式输出。

## 任务和审查

文字任务需要明确执行者，仅整理文字。正式审批必须通过专用入口，普通聊天中的赞同不改变审批。

勾选重要审查后：先独立分析；所有首轮意见完成后，由用户点击“明确开启交叉审查”；完整原始意见只披露给该轮指定审查者。可以保留拒绝、修改意见和分歧。审查记录分别填写一致意见、分歧、未解决问题和证据，不自动合成为共识。

修改任何快照关键内容会生成新版本，旧审批不能用于新版本。全部指定方明确无条件通过才能审议通过。用户授权另行记录，不会自动执行工程。

## 项目知识与差异观察

项目知识按事实、决策、研究、任务材料、文档、会议记录建卡。每次修改生成不可变版本，默认不共享；显式共享给选定角色后，还必须使用“附加知识版本”选定本次发送使用的版本。仅引用不会把其他版本或整个知识库自动发送给 Agent。

撤销授权会阻止新的投递，不能让已接收方忘记已读内容。不要将私有记忆、配置或凭证作为项目知识。平台没有读取/同步这些数据的功能，也没有替代 Mnemosyne。

选择 Agent 消息可记录差异观察。观察仅存说明，不评分、不改写原文、不推断意识。

## 本机安全

默认只有回环监听、Bearer鉴权、Host与Origin检查。没有公网/手机功能。保管 data 下的配置及 backups 私密备份；不要转发其中令牌。原网页调试入口不承担新版多项目业务状态，旧写入入口已禁用。
