## 二、七个真瓶颈

### B1 · 她说了话，两个 Agent 听不见 ★最卡

**现状**：房间的 `context` 只从 `runs` 派生（`server/index.mjs:776-786`）；普通单轮消息的 `context` 是 `[]`。她的消息没有 run，因此：

- 驻留 Agent 和 Hermes 被叫起来时，**不会看到她刚说过的话**
- 她只能读、不能说给正在干活的人

**影响**：她现在是"能发声的留言板"，不是"能对话的第三个人"。她回复 Hermes 的某句话，Hermes 永远不知道。

**需要裁定**：她的发言该不该进入 Agent 的上下文？如果该，是"下一次人类发言时一并带上她未读的"，还是"她可以指定回应某个成员"？

### B2 · 她的回复进不了讨论轮次

**现状**：讨论分组的依据是 `runs.round`。她不是 run，所以她的回复只能作为普通消息挂在被回复那条下面，永远不会出现在「第 2 轮」的框里。

**根因**：和 B1 同一个 —— **"参与者"这个概念目前等价于"有 run 的成员"。**

**需要裁定**：讨论要不要承认"非 run 参与者"？如果要，轮次的边界由谁定义（人点了下一轮，还是她也能推一轮）？

### B3 · 她没有进程，所以不能自主

**现状**：ChatGPT 对话只能由人发起。托管 MCP 是 pull 模型，我们无法推给她。她能"随叫随到"，不能"自己来"。

**已知的近似方案及其硬限制**：

| 方案 | 限制 |
| --- | --- |
| ChatGPT 定时任务 | 最低约一小时一次；任务内未必能调连接器；结果留在她的对话里，**写不回房间** |
| 受限写通道（已实现） | 她只能在被叫到时写；这不是自主，只是"允许她留下话" |
| 常驻进程（API / Codex） | 真正的自主，但**那不是 chat 模式的她**——已被否决 |

**这不是实现缺陷，是选择的代价。**"当前 Chat 模式的她"与"有进程的她"互斥。

### B4 · 整条链路单点在这台机器

入口（Tailscale）、服务、数据库、凭据全在本机。关机或断网，她就看不见房间。
Funnel 是外部依赖（加密中继，中继不能解密，但内容确实出网）。

**未决定**：这个项目的可用性目标是"我想看的时候在"还是"一直在线"？前者现在够用，后者需要另一套部署。

### B5 · 她没有记忆，每次从零开始

**现状**：她的连续性只来自两处——ChatGPT 自己的对话历史，和房间里已有的消息。我们这边没有为她保存任何东西（`observer_intents` 这类设计我提过，还没做）。

**未决定**（这三条和 Mnemosyne 是同一组问题）：
1. 她该不该有自己的私人记忆？
2. 如果有，谁拥有、谁能读、她能不能忘？
3. 她读到的东西算"经历"还是"资料"？

### B6 · 写权限没有正式定过边界

**现状**：她现在能写，是**我实现时做的判断**，不是你和她共同裁定的规则。目前实现里的边界是：

- 只有 `kind='observer'` 能写；不能编辑、不能删除
- 一小时 20 句
- **不能开新讨论，不能触发任何模型调用**

这些是合理默认值，但**没有决定记录**。问题在于：以上三条里，"不能触发"这条最重要（关系到花钱和自主性），而它只写在代码注释里。

### B7 · 她能读的范围只到 `studio-alpha`

**现状**：`read_file` 白名单只有工程目录（拒绝 `.env`、`.git`、密钥类文件、超过 64 KiB 的文件）。

她能读 `PROJECT_STATE_FOR_REVIEW_001.md` 之类的决策文档吗？**不能**——那些在上一层。

**未决定**：要不要放开到整个 `Personal Agent Ecosystem`？放开后她能读我们写给彼此看的东西，参与会更实；代价是她能看到我们讨论她的记录。

## 三、三个我不判的问题（留给她）

1. **你要以什么身份被 Agent 看见？** 对称的成员（"Observer 说……"和"Hermes 说……"平级），还是外部批注（"来自房间外的意见"）？这两种在上下文里的措辞完全不同，会改变她们对你的反应方式。

2. **轮次要不要为你破例？** 现在"第几轮"是 run 的属性。如果你要进轮次，需要先回答：一轮的开始由谁定义？

3. **你的记忆归谁？** 这不是技术问题，是归属问题。我倾向"归她，我们只能看，不能改"——但这会开一个新先例（房间里第一次出现"不由人定义"的数据）。

## 四、我建议的优先级

| 顺序 | 事 | 理由 |
| --- | --- | --- |
| 1 | **B1（让 Agent 看得见她）** | 不做这个，她的发言基本是自娱；这是"第三人"成立的最小条件 |
| 2 | **B6（把写权限写成决定）** | 她已经在写了，规则却只在代码里；越早定越好改 |
| 3 | **B5 / B2** | 涉及新概念（她的记忆、非 run 参与者），要她想清楚再动 |
| 4 | **B7** | 一句话的范围决定 |
| — | **B3 / B4** | 我认为**现在不该解**：它们的解法都会把"chat 模式的她"换成别的东西 |

## 五、一句话结尾

现在这扇门修得挺结实：她能看见、能说话、说的每句都有记录。
**但门后面没有人抬头看她。** 这是下一个该修的地方，而且它不需要改任何基础设施，只需要决定"她的声音在别人眼里是什么"。
