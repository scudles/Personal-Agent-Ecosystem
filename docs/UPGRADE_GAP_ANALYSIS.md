# 001差异与分阶段计划

## 原则

原生独立、协作集中、决策分散。扩展现有实现，保留旧Web调试入口；不改原生系统提示词、记忆、模型、原始Session。元数据统一不等于认知统一。

## 实际差距

P1：已有项目/会话归属与数据库隔离；新增项目说明、Member/ACL和受限访问者，补齐Binding证据等级及权限DTO。

P2：显式收件元数据已完成；补齐标准元数据别名及来源/幂等。用户已明确：回复默认发给被回复消息作者（例如Hermes），可以手动修改对象。已按此保留。

P3：已有独立首轮与全票闸门；新增所有首轮完成之后的显式交叉披露、原意见/修改/分歧分层记录，不能提前泄露其他人的初始意见。

P4：现有Adapter保留且硬锁真实访问；增加声明式统一能力接口。仅模拟方法可调用，不支持或未授权的真实方法明确拒绝。

P5：已有WPF；扩展原生多窗口入口，独立当前项目/会话状态，共用同一后台和历史；不复制会话。

P6：已有67项；增加001断言与真实时间至少2小时模拟稳定性。代码冻结后开始计时，记录代码哈希/进程/故障/间隔，不能加速或引用旧空闲时间。

Project Knowledge：新增项目内、用户授权、版本化文字知识卡。默认不自动分发，不读Agent私有记忆，不重复Mnemosyne。

## 迁移与回滚

当前Schema=1。新增Schema=2先在副本验证，再用在线一致性备份保存当前库。只增量增加字段/表，不重写旧历史；原库文件和83条原始归档哈希保留。回滚先停模拟后台，恢复到新文件，再切换databaseFile，保留当前文件；不回滚成可自动激活真实Adapter的旧启动方式。

## 风险

- owner单令牌不等同于受限主体的项目权限，应补ACL测试。
- 交叉审查不能提前披露；新轮意见不能覆盖原意见。
- 多窗应隔离UI状态但共享同一Workspace历史。
- 知识卡必须显式授权和引用，不能自动共享私有记忆。
- 原生接口当前只验证模拟；真实接入仍需单独授权。
- 2小时可能因进程退出、机器挂起或错误而失败，必须如实记录，不标为完成。
