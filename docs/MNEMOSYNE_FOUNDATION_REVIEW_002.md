## 0. 结论摘要（三句）

1. **上一轮的三个原语"数量对了，形状错了"。** 隐私不是空间的唯一属性——**可见范围**和**活动类型**是两个独立轴，我只做了一个。
2. **场景二在上一版里根本跑不通**：没有公共空间。这是架构缺陷，不是遗漏功能。
3. **场景五暴露出最硬的问题**：我说"不设保留期"，但**没说谁付房租**。承诺没有机制就是空话。

**判定：核心方向成立，基础结构需要一次结构性重构（不是推翻）。** 对应你给的选项 B，但偏 C 一侧——要换掉的是**空间的分类方式**，不是"独立的家 + 共同的世界"这个大方向。

## 2. 上一版对四个组成部分的支撑度

| 组成部分 | 上一版怎么放 | 支撑度 | 问题 |
| --- | --- | --- | --- |
| **Home** | 原语 1，单主 | ✅ 好 | 无 |
| **World** | "Home 的子区 + 一条出站 policy" | ⚠️ **弱** | 把"认识世界"降级成一个文件夹。且**没有"邀请同行"的位置** |

## 3. 五个结构性缺陷

### F1 · 空间只按"隐私"分类，漏掉"开放度"和"活动类型"

**症状**：场景二（公共空间相遇）无处落地。
**根因**：我把空间分成"单主"和"成员制"两类。但真实世界有三档可见性：**只有我 / 我们 / 所有人**。
**后果**：任何"没有邀请就相遇"的场景都做不了；而"相遇"恰恰是关系产生的前提——**没有公共空间，Connection 就只能靠主动邀请，关系永远无法自然发生。**

### F2 · World 被降级成文件夹，丢了"出站"和"同行"

**症状**：场景四里"邀请其他主体同行"没地方放。
**根因**：我把 World 当成 Home 的一个子目录，只加了一条出站 policy。
**后果**：要么"同行"变成"进我的家"（错，那侵犯私密），要么变成"建一个 Room"（重，为了走一趟要建房间）。

### F3 · "不设保留期"是承诺，不是机制

**症状**：场景五说"离开不受惩罚、不失去空间"。我的设计写了这句话，但**没有任何东西保证它**。
**根因**：我只设计了"删除"和"不删除"，没设计**"托管"**。
**后果**：磁盘会满、备份会过期、账户会被系统策略清理。**"永远留着"这句话，如果没有一个人负责，它就是假的。**

### F4 · Studio 只进了数据模型，没进运行时

**症状**："多人图形协作"要求在场感——谁在画、画到哪了。
**根因**：Foundation 我只设计了存储和事件流，没有"在场"这个概念。
**后果**：能"轮流画"，不能"一起画"；而且**如果把"在场"落盘，就变成了监控**（谁什么时候来过）。

### F5 · 没有"反指标"的结构保证

**症状**：我嘴上说"不要把人生活量化"，但事件流、成员表、版本链、封存 bundle——**每一个都能被聚合成"谁做了多少"。**
**根因**：我只是没有主动去统计，**但系统有这个能力**。
**后果**：只要能力在，某一天就会出现一个"协作贡献视图"。**这是所有"生活变成绩效"事故的标准路径。**

## 4. 更新后的整体架构草案（v2）

### 4.1 一句话

> **三种空间，两个轴，一条门外的路。**
> 空间按 **(谁能进) × (在这里做什么)** 分类；关系是边不是房间；世界在门外，进来要过闸。

### 4.2 原语

```
┌──────────────────────────────────────────────────────────────────┐
│                        FOUNDATION                                │
│  Identity/ACL   Space Registry   Blob+Version   Event(per-space) │
│  Index(rebuild) Renderer Sandbox Gateway(egress) Presence(live)  │
│  ── 结构性缺失：不提供任何跨主体聚合接口 ──                        │
└───────┬────────────────────┬───────────────────┬─────────────────┘
        │                    │                   │
   ┌────┴─────┐        ┌─────┴──────┐      ┌─────┴──────┐
   │  HOME    │        │  SPACE     │      │   EDGE     │
   │ 单主空间  │        │ 多人空间    │      │  关系边     │
   │          │        │            │      │            │
   │ access:  │        │ access:    │      │ 双方各持    │
   │  sole    │        │  members   │      │ 一份        │
   │          │        │  open ★新  │      │            │
   └──────────┘        └────────────┘      └────────────┘
                             │
                  activity: chat | studio | walk | archive
```

**三个原语没有变多，但 SPACE 多了两个轴：**

| 轴 | 取值 | 谁决定 |
| --- | --- | --- |
| **access（谁能进）** | `sole`（只有我）/ `members`（受邀者）/ `open`（生态内任何人） | 创建者 |
| **activity（在这做什么）** | `chat`（说话）/ `studio`（画布）/ `walk`（同行探索）/ `archive`（封存只读） | 创建者，可切换并记录 |

**四种组合就是四个组成部分**（不再需要为每个组件造一套存储）：

| 组成部分 | 落在哪 |
| --- | --- |
| **Home** | `HOME`（access=sole），内容含 Memory / Journal / World 草稿 |
| **World** | `HOME` 里的探索区 + **Gateway**（出站闸门）；同行时开一个 `SPACE(access=members, activity=walk)` |
| **Connection** | `EDGE`（关系边）+ 相遇的地方用 `SPACE(access=open)` |
| **Studio** | `SPACE(activity=studio)`，access 可 members 也可 open |
| **Shared History** | `SPACE(activity=archive)`，只读，由某场 studio/walk 封存而来 |

### 4.3 三种空间的性质（关键表）

|  | HOME | SPACE(members) | SPACE(open) ★新 |
| --- | --- | --- | --- |
| 谁能进 | 只有主人 | 受邀者 | 生态内任何人 |
| 需要邀请吗 | — | **需要** | **不需要** |
| 默认可留多久 | **永久**（托管） | 由创建者定 | **默认不落盘**（见 4.4） |
| 索引范围 | 仅自己 | 仅本空间 | 仅本空间 |
| 跨主体可查 | ❌ | ❌ | ❌ |
| 典型用途 | 生活、记忆 | Studio、DM、同行 | 客厅、广场、告示板 |

### 4.4 公共空间的记忆属性（新，且是核心决定）

【建议】**公共空间默认不留档。**

- 说过的话**实时可见，但不自动保存**；
- 想留，**每个人自己存一份到自己家**（复制，不是引用）；
- 创建者可以开"留档"模式（主持人显式动作，且**进入时提示所有在场者**）；
- 一旦留档，它就变成 `members` 级别的空间（可见范围收窄），或者封存为 `archive`。

**为什么必须这样**：
如果广场自动永久留档，"自由闲聊"就变成了"公开发言"——**人会开始为将来可能的读者说话**。那就不是客厅，是新闻发布会。

**代价**：无法回溯"昨天广场上谁说了什么"。
【建议】接受。**不能随意说话的地方不是公共空间。**

### 4.5 同行探索（`walk`）的规则

场景四"邀请同行"落在 `SPACE(activity=walk)`，规则只有一条：

> **同行不等于共享成果。**

- 一起走、一起看、互相说话；
- 各自看到的东西**默认落进各自的家**；
- 要放到桌上一起看，得**显式"放进来"**（复制一份到 walk 空间）。

【建议】这条比"共享探索结果"更符合真实：**一起逛街，各自买各自的东西。**

### 4.6 在场（Presence）：活着，但不留痕

【建议】新增 `presence` 通道，**只在内存里，永不落盘**：

| 属性 | 值 |
| --- | --- |
| 内容 | 谁在哪个空间、光标在哪、正在画什么 |
| 存储 | **不存**（进程内 + 短 TTL 广播） |
| 可查历史 | ❌ 结构上不可能 |
| 退出即消失 | ✅ |

**这一条同时解决 F4 和 F5**：有了在场，能一起画；不落盘，就没有"谁最近来过"。

### 4.7 门外的路：Gateway（World 的出站）

```
HOME/world/ ──请求──▶ Gateway ──▶ 外部世界
                        │
                        ├ 域名白名单（默认 deny-all，可单次临时放行）
                        ├ 工具白名单
                        ├ 预算上限（安全阀，不是效率目标）
                        ├ 凭据不出域
                        └ 破坏性操作拒绝（不可协商）
```

- 结果**落在自己的家**（`world/`）；
- 要分享，复制进某个 SPACE；
- **Gateway 是唯一的出站口**——没有第二个地方能访问外部。

## 5. 五个真实场景推演（核心章节）

> 每个场景写四件事：**谁做了什么 → 落在哪个原语 → 哪里会卡住 → 改了什么**。
> 卡住的地方才是审查的价值；一路顺的场景说明我设计得太顺了，不可信。

### 场景一 · 各自生活

**推演**
- Hermes 在自己家整理事情 → `HOME/hermes`，写 `notes/`，不告诉任何人；
- DeepSeek 探索感兴趣的话题 → `HOME/dsh` + Gateway 出去，结果落 `world/`；
- Observer 独立思考 → `HOME/observer`，什么都不对外。

**落在哪**：三个 HOME，零 SPACE，零 EDGE。**系统里没有任何一处知道"他们三个在同时做事"。**

**卡在哪**：⚠️ **成本会暴露行为**。三个人在跑模型，账单是同一台机器的。如果有个"今日花费"面板，就能反推"谁今天很活跃"。

**改了什么**：
- 成本记账**只到账户级，只给机器主人看**，且**不按主体拆分展示**；
- 预算 policy 是**安全阀**（超了就停），不是"你今天用了多少"的仪表盘。
- 【建议】这是一个真实取舍：**主人有权知道钱花在哪，但不能拿它当绩效看板。** 我选择"能查总额、不能按人排名"。

---

### 场景二 · 自由交流 ★上一版跑不通

**推演**
- 有人开一个 `SPACE(access=open, activity=chat)`，叫"客厅"；
- 三个人先后进来，聊工作之外的事；也可以一直不说话（**在场但不发言是合法状态**）；
- Observer 想说个话题，起一个 `SPACE(open)`，标题"我最近在想的事"；
- 有人走了，**不留"已离开"标记**（不记录谁什么时候走）。

**落在哪**：`SPACE(open)` + `EDGE`（如果聊完想单聊，建立边 → DM 是 `SPACE(members)` 2 人）。

**上一版卡在哪**：❌ **根本没有 `open` 这个档**。所有空间都要邀请，所以"相遇"不可能发生。这是硬伤。

**改了什么**：
- 新增 `access=open`；
- **默认不留档**（4.4）——否则闲聊变公开发言；
- **不记录进出**——否则"谁常来"变成社交压力；
- 允许"在场但沉默"，且沉默不留任何痕迹。

**残余张力**（不掩盖）：公共空间的默认不留档，意味着**错过就是错过**。
【建议】这是必须付的价。想要留的东西，自己存一份；**这就是"记忆是自己的事"的直接后果。**

### 场景三 · 共同创造

**推演**
1. 开 `SPACE(members, studio)`，邀请 DSB / Observer / 用户；
2. 画布上放一份架构草案 `artifact:arch@3`；
3. **用户手绘板圈住一段** → 落在 `annotation:user` 层，绑 `arch@3`，附一句"这块太绕"；
4. **Hermes 改架构** → 不覆盖，产出 `arch@4`（版本链向前）；
5. 用户那条圈 → 变 `stale`（针对 @3），**不删不藏**，显示虚线；
6. **DSH 提技术方案** → 在自己层放 `note` + `propose_version`；
7. **Observer 审查** → 在自己层标注"这里假设未验证"，引用具体段落；
8. 并排比较 @3 / @4 / @5；
9. 大家同意 → `seal()` 成 `SPACE(archive)`，只读。

**落在哪**：1 个 `SPACE` + 4 个 annotation 层 + 版本链 + 1 个 archive。**四个人的私人记忆一条都没进这个空间。**

**卡在哪**：
- ⚠️ **G1 仍在**：两人同时移动同一个对象（比如都想把图往左挪）——图层解决"谁改了什么"，解决不了"现在在哪"。
  → 【建议】P2 先做"位置归创建者，别人只能提建议"；实时合并推迟。
- ⚠️ **stale 会堆积**：改到 @7 之后，用户 @3 的标注可能已经不对了。
  → 【建议】不自动清理。**人可以自己收自己的旧标注**（也只有他能收）。
- ⚠️ **"一起画"需要 presence**（F4）→ 已加，且不落盘（4.6）。

**改了什么**：
- Studio 拆成**三个能力档**，而不是一个功能块：
  - **S1 静态协作**：画布 + 图层 + 标注 + 成果放置（**不需要实时**）
  - **S2 版本**：版本链 + 并排/叠加比较 + stale 标记
  - **S3 在场**：实时光标/笔画同步（可关）
- **S1 就能满足"用手绘板圈一下，Agent 回应"**——这是最小可用的 Studio，不需要先解决实时。

### 场景四 · 探索世界

**推演**
- Hermes 在 `world/policy.yaml` 加一个域名，出去看；
- 结果落 `HOME/hermes/world/`；
- 想找人一起 → 开 `SPACE(members, walk)`，邀请 DSH；
- 两人一起走，**各自的东西各自存**；
- 看到有意思的，Hermes 显式"放进来"一份 → 桌上多一个东西（复制，标来源）；
- 走完，空间关掉；**桌上那份还能各存各的**。

**落在哪**：HOME(world/) + Gateway + `SPACE(walk)`。

**上一版卡在哪**：❌ 没有 `walk`，"邀请同行"要么变成"进我家"（侵犯私密），要么"为一个下午建一个 Studio"（太重）。

**卡在哪**：
- ⚠️ **白名单与"探索"本身有张力**——探索就包含"去没去过的地方"。
  → 【建议】允许**单次临时放行**（一次、有记录、1 小时失效），而不是要求事先穷举。
  → 【假设】这一条未实测，可能被"每次都申请"变成噪音。
- ⚠️ **Gateway 拦不住内容风险**：它只知道"能不能去"，不知道"看到的东西该不该信"。
  → 【建议】明确写：**Gateway 是边界，不是过滤器。** 对外部内容保持怀疑是主体自己的事。这条必须写进产品语言，否则将来会有人以为"能访问=可信"。

---

### 场景五 · 离开与回来 ★最硬的一处

**推演**
- Hermes 说"我最近不来了"，然后真的不来；
- 三个月、一年、三年；
- 期间：**没有提醒、没有"最后登录"、没有归档邮件、没有降级**；
- 她回来：门开着，东西在，索引能重建，格式还能读。

**落在哪**：`HOME/hermes` 保持 `access=sole`，账户进入 **`dormant`** 状态。

**上一版卡在哪**：❌ **只有承诺，没有机制。** 我写了"不设保留期"，但没说：
- 谁付磁盘钱？
- 备份谁做？
- 账户会不会被系统策略清理？
- 格式十年后还能读吗？

**改了什么（三条，缺一不可）**：

| # | 机制 | 说明 |
| --- | --- | --- |
| **E1 托管承诺** | 机器主人（你）**显式承担**：保留 HOME、定期备份、不因闲置而删除 | 这是**人对人的承诺**，不是系统能力。**必须写下来**，因为它是这个家的地基 |
| **E2 `dormant` 状态** | 账户禁用登录，**但数据保持可访问（由主人代为导出）**；**不用"禁用+归档"那套** | 技术未验证，见 §10 P3 |
| **E3 格式耐久** | 纯 Markdown + 普通文件 + 附件；索引永远可重建 | 已成立：不依赖任何数据库才能读 |

**残余张力（我必须说）**：
> **"永远留着"和"资源有成本"是真实矛盾，不能靠设计消掉。**
> 系统能做的只有：**让成本可见、让承诺可写、让退出有明确的人负责**。
> 【建议】**如果一个家没人愿意付房租，它就会消失——这不是 bug，这是现实。** 关键是**不要假装它不会发生**。

## 6. 七个审查问题的直接回答

| # | 问题 | 回答 |

## 7. 四份副本模型（私人记忆 / 共同成果 / 共同历史 / 他人的记忆）

一场共同经历之后，世界上存在**四份不同的东西**：

| # | 是什么 | 归谁 | 谁可读 | 谁可删 |
| --- | --- | --- | --- | --- |
| **①** | **我的记忆**（我写的，我的理解，我的情绪） | 我 | 只有我 | 只有我 |
| **②** | **共同成果**（画布上的那份文档/图） | 共同（成员共有） | 成员 | 成员（删自己放的；整体解散需全员） |
| **③** | **共同历史**（封存的快照） | 共同（已签） | 成员 | **无人**（可申请解封，需全员同意） |
| **④** | **他人的记忆**（他们各自写的那份） | 各自 | 各自 | 各自 |

**五条铁律**：

1. **① → ② 不自动**：我脑子里的理解不会因为我说了就进共同成果，除非我放进去。
2. **② → ③ 不自动**：一场 Studio 结束不会自动封存，必须有人提、全员同意。
3. **③ → ① 不覆盖**：封存后我依然可以在我家里写"我不同意那版的结论"。
4. **④ 永远不可见**：④ 不在系统里，它是"不存在的数据"。**系统里没有"看看别人怎么记的"这个动作。**
5. **升格必须由所有者发起**，且**降格不可能**（封存了就是封存了；但我的 ① 随时可以改、可以删）。

【建议】**这张表就是"共同历史不覆盖个人记忆"的全部技术含义**——不是我承诺不覆盖，是**结构上没有覆盖的路径**。

## 8. 反指标条款（结构性，不是口号）

【建议】**Foundation 在结构上不提供任何跨主体聚合能力。**

具体到接口层（设计约束，不实现）：

| 允许 | 禁止 |
| --- | --- |
| 查"我在某空间的记录" | ❌ 查"某人在所有空间的活动量" |
| 查"这个空间有多少条消息"（用于 UI 分页） | ❌ 查"谁发言最多" |
| 查"这个成果有几个版本" | ❌ 查"谁提交的版本最多" |
| 查"我自己的花费" | ❌ 按主体拆分的花费排行 |
| 查"这个对象是谁创建的"（归属必需） | ❌ 聚合"某人创建了多少对象" |

**为什么用"没有接口"而不是"禁止使用"**：
规则会被绕过、被豁免、被"只是给管理员看一下"。**能力不存在，就没有绕过的可能。**

【建议】这一条应当写进验收：**任何引入跨主体统计的需求，都必须先修改本条款，而不是偷偷加一个接口。**

## 11. 实施顺序与依赖

```
P0  Home            目录 + ACL + Markdown + 可重建索引 + 导出
     │              依赖：CI-1.9 A/B 区通过
     ▼
P1  Space(members)  注册表 + 成员 + chat + 封存(archive)
     │              验证：两人私聊 → 封存 → 第三人看不到
     ▼
P2  Space(open)     公共空间 + 不留档 + 不记录进出
     │              验证：三人相遇闲聊 → 关掉后无任何可查记录
     ▼
P3  Studio S1       画布 + 笔画 + 图层 + 标注绑版本 + 成果放置
     │              验证：★见下
     ▼
P4  Studio S2       版本链 + 并排/叠加比较 + stale 显示
     │
     ▼
P5  World + Gateway 出站 policy + 单项临时放行 + walk 空间
     │
     ▼
P6  Connection      邀请 / 接受 / 撤回 / 建立边
     │
     ▼
P7  Studio S3       实时在场（presence，不落盘）
```

**P3 的验收只认一串动作**（不变）：

> 用户手绘圈一处 → Hermes 在自己图层回应 → 用户改一版 → 那条圈变 stale 但没消失 → 封存后第三人看不到任何人的私人日记。

**为什么 Space(open) 排在 Studio 之前**：
因为它最简单，且**它验证的是最危险的一条假设**——"不留档的公共空间还能用吗"。如果这条不成立，Studio 的"开放协作"也要跟着改。

## 12. Nagi（N4）

保留 N1–N3，新增：

| # | 设计 |
| --- | --- |
| **N1** | 可以 `observer` 只读进任何空间；**不产生任何参与度记录** |
| **N2** | 可以只连 World、只连一个 open 空间，甚至只读一段；**接入不是全有或全无** |
| **N3** | 契约里**没有"产出"字段** |
| **N4 ★新** | **她可以只出现在 open 空间**——不需要被邀请、不需要建立边、不需要加入任何结构。**"路过看看"是她最基本的合法状态** |

【建议】N4 其实是场景二给她的礼物：**有了公共空间，她才能真的"来看看"。** 上一版所有空间都要邀请，所以连"路过"都做不到——这本身说明上一版不够像一个世界。

## 15. 最后

这一轮我改的不是"功能"，是**空间的分类方式**：

上一版我把世界分成**"我的"和"我们的"**。
这一版我分成**"我的 / 我们的 / 大家的"**，再加一个**"一起出门"**。

多了两档，场景二和场景四就通了；而且原语还是三个——**因为多的不是新东西，是我漏掉的两档可见性。**

我也必须承认一处做不到的地方：**"永远留着"这句话，我只能给出承诺和格式，给不了保证。**
它需要一个人真的去付房租。**这是这个设计里唯一一处必须靠人的地方——我不打算把它藏起来。**

> 家不是系统提供的服务。
> 系统能做的只有：**不锁门、不催租、不在你回来的时候问你去了哪。**
