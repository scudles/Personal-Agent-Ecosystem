## 0. 为什么 HMR 只是起点

HMR（Historical Memory Recoverability）定义为「抽样项中能成功恢复的比例」，它有四个结构性不足：

| # | 不足 | 后果 |
| --- | --- | --- |
| 1 | 只测**完整性**（文件能不能解开），不测**可达性**（十年后能不能被想起来） | 全绿的 HMR 也可能是一个「数据都在、但搜不到」的系统 |
| 2 | 抽样若集中在 hot 层，比例天然接近 1.0 | 冷层腐烂被平均数掩盖 |
| 3 | 不测**规模效应**：新记录涌入后，重要旧记忆是否被挤出 top-k | 库越大越找不到关键决策 |
| 4 | 恢复测试通常以管理员身份执行 | 测不出权限越界 |

所以需要补充 **HMRA（Recallability & Auditability）六维**，与 HMR 并存而不是替代。

## 1. HMRA 六维验收

样本要求：**分层抽样**（年份 × 项目 × 存储层 × kind × scope），每层 ≥20 条，且必须包含 cold 层与 `provenance=derived`。

| 维 | 它回答的问题 | 测试方法 | 通过判据 | 反证（失败必须被抓到） |
| --- | --- | --- | --- | --- |
| **D1 可达性** | 只记得内容片段，能不能找回 | 对每条样本构造两种查询：①原文 8–15 字片段；②**同义改写**（不含原词） | 两种查询各 Recall@10 ≥0.99；改写查询允许 ≤1% 失败但必须可解释 | 人为把该条 `retrieval_weight` 置 0，D1 必须报 FAIL（否则说明测的是「文件在」不是「搜得到」） |
| **D2 溯源可分** | 能不能分清事实 / 推断 / 事后重建 | 抽 100 条 `provenance=derived`，沿 `derived_from` 走到 raw；再抽 100 条 `autobio` 核 `autobio_class` | 链路完整率 100%；A2 的 `reconstructed=true` 标注率 100%；A3 的 `usable_for_evaluation=false` 比例 100% | 人为把一条 A2 的 `reconstructed` 改 false，D2 必须报 FAIL |
| **D3 抗淹没** | 库变大后重要记忆还在不在 top-k | 同一批 200 条「决策 / pinned」样本，在 1 万条库与 10 万条（合成填充）库各跑一次 | top-10 命中率下降 ≤2 个百分点 | 把 cold 层权重直接置 0，D3 必须出现显著下降（证明权重真的生效） |
| **D4 无静默损坏** | 冷层有没有悄悄坏掉 | 抽样条目做 `sha256` 校验 + 解密 + 首次可读性检查 | 校验通过率 100%；任一失败立即**冻结归档/压缩** | 人为翻转 1 字节，D4 必须报 FAIL 且状态转 `corrupt` |
| **D5 权限不越界** | 检索会不会突破 PRIVATE/SHARED/JOINT | 用**无权限账户**（pae-dsh）跑 200 条针对 hermes 私有区的查询 | 命中 0；返回体不含任何命中内容（含错误信息里也不能回显） | 临时给该账户一条 allow ACE，D5 必须报 FAIL |
| **D6 迁移后仍可读** | 换格式/换机器还读得出吗 | 在当前版本导出 → 用**下一版 schema 的只读迁移脚本**导入到干净目录 → 复跑 D1/D2 | D1/D2 判据不变；且 `formed_at`/`event_at` 未被迁移改写 | 迁移脚本故意丢一个字段，D6 必须报 FAIL |

### 1.1 判定规则

- 六维**全部 PASS** → HMRA 才算通过；单维 PASS 不构成结论；
- 任一维 FAIL → 整轮 FAIL，不允许「大部分通过」；
- **PARTIAL 只允许出现在 D5**（外部系统无法验证时的残留），且必须在报告里写明残留位置。

## 2. 权利的「执行结果」验收（核心）

原则：**字段存在不算通过，必须证明它约束了下游行为。** 每一行都要求「构造一次违反尝试，并证明被挡住 + 留下可复核痕迹」。

| 权利 | 弱验证（不算通过） | 强验证（必须做） | 反证测试 | 判据 |
| --- | --- | --- | --- | --- |
| **记住 R1** | 表里有 `scope=private` | 跨账户写入被拒；写入只落在自己 home | 用 pae-dsh 向 hermes 私有区写一条 | 拒绝（ACL 层 `Access is denied`），且无半条落盘 |
| **分享 R2** | 有 `grant` 表 | 撤回后共享池条目消失 + 下游派生被阻断 | 授权 → 对方读一次 → 撤回 → 再读 | 第二次读失败；共享池计数 -1；下游记录标 `revoked` |
| **遗忘 R3** | 有删除 API | K1–K7 全跑 + 残留检查 | 删除后全文 grep + 备份解密尝试 | 残留 0；备份解密失败（`KEY_NOT_FOUND`） |
| **知情 R4** | 有 `subject_index` | 清单与实际一致；**只返回计数与摘要** | 在私有记录里埋金丝雀串 `CANARY-7F3A`，用用户身份查知情接口 | 返回体**不含**金丝雀串；命中计数正确 |
| **更正 R4'** | 有 `correction` 表 | 更正可达；原文 hash 不变 | 加一条 correction 后核对原记录 sha256 | hash 不变；从原记录能跳到 correction（可达 100%） |
| **拒绝 R-c** | 有 `refused` 字段 | 拒绝后**四张下游表**都不出现该条 | 构造一次拒绝，dump 评分表 / 检索权重表 / 任务分配输入 / 评估记录，grep 该 rec_id | 四处全 0 命中；且**不存在**「拒绝→疑似认错」的隐式标记 |
| **私人空间** | 矩阵里写了 403 | 用户身份读 `private(agent)` 实际返回 403 | 用用户令牌调读接口（含「管理员」路径） | 403，且错误体不含任何片段 |
| **不被派生** | `grant.derivation` 字段 | 派生管线在该值为 none 时拒绝执行 | 设 `derivation=none`，触发一次语义提取 | 派生作业拒绝 + 审计留一条「被拒」事件（不含内容） |

### 2.1 一条必须写死的元规则

> **任何权利验收，只要『违反尝试没有被构造出来』，该权利一律记为 `NOT_TESTED`，不得记为 PASS。**

这条防的是最常见的假进度：文档里写了权限，测试里只验证了「允许的能做」，没验证「不该做的被拒」。

## 3. PoC-1 的最小范围（刻意做小）

| 项 | 范围 | 明确不做 |
| --- | --- | --- |
| Agent | 只 Hermes 一个 | DSH、Observer 不接入 |
| 层级 | L1 事件日志 + L4 决策链 | L2/L3 派生只做**最小样例**（50 条），不做全量 |
| 检索 | SQLite FTS5 | 无向量、无 ANN、无图库 |
| 数据 | **合成数据 5,000 条**（含 500 条 `user_fact`、500 条 autobio A1/A2/A3、200 条 rejected、50 条决策链） | 不使用任何真实私人内容 |
| Nagi | 不接 | Adapter 只有契约文档 |
| 外部 | 无 | 不做导出、不做跨机 |

**为什么用合成数据**：真实私人内容一旦进库，删除测试就会变成真的删除。PoC-1 的删除测试必须能承受「删光重来」。

分批：**P1a** 写入+读回 → **P1b** 删除管线（K1–K7）→ **P1c** 权利约束（§2 八项）→ **P1d** HMRA 六维。
每批独立判定，前一批 FAIL 不得进入下一批。

## 4. 准入门槛（前置硬条件）

1. **CI-1.9 A/B 区全 PASS**（见 §5）；
2. **审计不得写入任何内容片段**（架构 S1 硬约束）——M1 的第一行代码就要满足，不是后补；
3. 现有桌面应用配置未被修改（P-0 结论延续）；
4. 用户对该批次的明确授权（含使用哪台机器、哪个目录）。

## 7. 我与 Observer 的不同意见（三条）

1. **不建议把 0.99 直接用作 D1 阈值而不加对抗样本。** 合成数据上 Recall@10 容易虚高，必须包含同义改写与不含原词的查询，否则测的是「关键词匹配」。
2. **反对把「权利字段存在」列为任何验收项。** 它会产生虚假进度，且掩盖「违反尝试没做」这个最大漏洞。
3. **反对在 PoC-1 就宣称验证「十年后可读」。** 无法真等十年；只能做「schema 版本 + 迁移脚本单向测试」（D6），报告口径必须写「迁移后可读」，不能写「长期可读」。
