## 当前业务入口及真实结果

新增 `POST /api/workspaces/:workspaceId/intent`，由 `src/collaboration-intent.mjs` 的本机有界适配器解析并调用既有工作流。它不是模型调用，没有新增Runtime、后台Agent、自主讨论调度或真实Adapter。HTTP入口继续核对回环Host、Bearer身份、Origin、local-owner权限、project / workspace作用域及既有幂等键；Agent凭证不能调用此意图入口，跨作用域对象不接受。

| 已支持的请求 | 进入的既有动作 | 可报告的结果边界 |
|---|---|---|
| 明确向一名Agent委派单个文字任务 | `textTask` | 实际事项ID与投递记录；已排队不等于收到或完成 |
| 对明确原文 / 事项发起独立复核或正式文字审查 | `createReview`，`reviewPlan=independent` | 真实文字审查快照与队列；复核者区别于任务负责人；不产生实施授权 |
| 对准确工程包版本请求必要复核 | Governance Host `startReview` ＋ Exchange `queue` | 实际审查轮次ID及模拟材料排队ID；不调用收件、确认、上传或结论接口 |
| 查询选中或唯一当前任务状态 | 当前事项及其投递记录只读查询 | 保留UNKNOWN等原状态；不新增任务 / 投递 |
| 按MAG询问第三方是否需要 | 读取生效MAG-001及风险规则 | 只解释现行规则，不自动猜测当前任务风险、不默认强制三方 |
| 定向请求总结 | 带原文上下文的 `chat` 请求 | 只报告总结请求已建立，尚未收到总结回复；平台未生成语义总结 |
| 有明确接收者的普通交流 / 回复 | 原 `chat` / 回复关联 | 原文定向排队，不自动升级为任务、审查或授权 |

常见已知上下文复用现有任务、负责人、版本、范围和根事项限制；目标缺失或多个任务冲突时返回 `CLARIFICATION_REQUIRED`，只追问当前缺失的对象。单个任务、文字审查要求一名负责人或必要复核者。已有文字审查复用原审查 / 修订入口，不无依据另建一轮。任务根事项的预算、期限、暂停、链长，以及知识版本授权继续沿用原核心校验。排队不足时回滚，不把返回了事项对象误报为已安排。

工程包复核要求准确版本和该任务已冻结的治理定义；必要复核者必须与定义相符。缺失治理、版本或对象有歧义时不猜测，也不悄悄退回文字审查。已有匹配审查返回只读查询结果，不重复发起；已有投递但无匹配审查时要求先核对，不把UNKNOWN或人工尝试隐式重投。新建轮次与模拟排队处在事务内。成功提示明确“未上传、未确认收件、尚无审查结论”，返回 `realAgentReceived=false`、`executionAuthorized=false`。

## 定向、原文与证据隔离

识别只处理用户当前有效正文。Markdown围栏、行内代码、缩进代码、块引用及引号内材料不参与收件者 / 动作识别；原材料仍保留供正常消息或明确上下文引用使用。普通名字提及不会扩大路由。开头明确 `@Hermes` / `@DSH` 等地址优先于输入区默认；单独的自然定向句式也可选定对象。没有可确定对象时不投递，回复Agent默认原作者，原作者不可用时不转给别人。

显式开头 `@全部` / `@all` 仅指**当前会话全部有效参与者**；每个目标都必须模拟可用。任一目标暂停、未绑定或不可用时整条不执行，不跳过不可用者形成部分广播。引用、代码和普通正文中的 `@all` 不触发广播。此能力不授予真实会话投递权，也不使单负责人任务变成多负责人。

普通聊天的业务正文保持用户原文，不因为存在隐藏选中任务就追加事项ID、哈希或旧包内容。确实需要上下文的任务、审查及总结请求，可以附上明确标记的原文引用；引用不代表已完成或获得授权。对象ID、版本、artifactHash放入结构化 `source.collaborationIntent.context`；用户输入放入 `originalText`，与供工作流使用的正文分别保存。WPF正常时间线优先展示用户原输入，完整原业务消息及逐目标投递记录仍在来源 / 技术详情可查。

受信元数据只能由模块内导入的 `INTENT_MESSAGE_METADATA` Symbol传入，`workbench.mjs` 在创建用户消息时读取该Symbol。HTTP JSON中的 `messageMetadata`、`source` 或同名字串属性不能伪造这一通道；它不是新增数据库列或外部可写的显示覆盖字段。

独立首轮意见隔离同时覆盖 `independent` 与 `independent_then_cross`：初始意见未全部提交时，当前引用 / 总结涉及这些意见会明确未执行，不把其内容提前交给其他Agent；全部意见提交也不自动广播，仍需后续明确动作。

## 明确保留的语义边界

这是规则覆盖的单动作适配器，尚未覆盖任意自然语言。识别到条件链、多步协作、复杂多Agent分工、正式用户批准、实施授权、解除暂停、补票 / 代投票、上传附件、真实原会话投递或修改MAG等请求时，返回未执行；不将这些已识别的受保护动作降级为成功聊天。已有测试覆盖相应句式，不据此声称所有同义表达均可可靠判定。

例如“让Hermes负责实现，DSH复核，ChatGPT暂不参与”整体未执行；“我正式批准这个方案”不会写入授权记录。普通赞同也不构成审批。缺失、歧义、不支持及执行异常保留输入；WPF只在匹配当前会话、原草稿及回复状态且后端返回EXECUTED时清理已发送输入。任务、审查、修订、精确治理分工和版本绑定的用户决定继续有保留的按钮入口，不为缩短操作而绕过授权边界。

## 右侧上下文与异常

`desktop/UxPresentation.cs` 校验 `State.scope` 与当前项目 / 会话一致后才显示或发送；切换作用域先清空旧摘要及旧选择，异步结果以Epoch和当前选择核对。接收者列表清空 / 恢复处于事件抑制区，防止清空控件时把目标会话的已保存接收者改成空。

上下文优先使用正在回复的原事项，其次使用最近明确选择 / 获得键盘焦点的消息、任务、材料或治理对象；无明确对象且仅一个相关事项时才采用唯一对象。`BuildUxIntentRequest` 只在最新明确对象为材料时携带当前会话的包ID / 版本，不把材料页残留选择暗中带进别的任务、消息或普通交流。对象冲突仍由后端再次核对。

右栏分别显示参与者接入状态、任务与本版投递、材料版本及审查 / 用户决定；“模拟绑定就绪”不叫原生Agent在线。模拟接入暂停、全局暂停、会话暂停及单方投递暂停分别保留。异常条独立于右栏折叠：消息UNKNOWN / 失败、任意当前会话材料UNKNOWN（包括未选中的材料包）、模拟绑定暂停、回执版本 / 哈希不匹配、P0/P1及需要用户处理的事项仍可发现；UNKNOWN明确不自动重发。

本机文件校验仅记录匹配所选包版本的校验时间，并标“非实时”；模拟收件核验要求匹配包、版本、快照、Manifest哈希、文件数量及 `SIMULATED_BYTE_VERIFIED`，并要求 `simulation=true`、`realAgentReceived=false`。人工交付报告不提升为字节验证或真实收件。材料尚未加载明确显示待加载，后台刷新失败明确可能是旧数据并显示最后成功刷新时间，不把未知解释成无材料或成功。原始逐目标状态保留；已排队、提交、收到回复、任务完成和用户授权仍分开。
