# 安全与权限边界

基准日期：2026-11-07。以下是项目执行原则；具体身份认证、权限模型和备份机制仍**待设计/待确认**。

## 权限主体

- 用户：最终决策者，提出目标、审核重要决定、批准高风险操作并控制整体权限。
- Hermes 与 DSH：平级。普通任务可在明确授权范围内双向委派；各自保留独立配置、工具、执行环境与私人记忆。
- Observer：独立审查，默认只读。不得擅自修改其他 Agent 配置、安装插件、删除文件、改变权限或执行高风险操作；不拥有执行管理权限。

## 必须由用户授权的操作

- 购买服务或消耗额外付费额度。
- 删除重要数据。
- 向外部发送消息。
- 修改系统安全设置。
- 扩大 Agent 权限。
- 执行不可逆操作。

授权机制**规划中**。在机制建立前，不能把普通任务授权推定为上述操作的授权。

## 数据隔离与记录

- 仅共享经过授权的项目资料；不得未经授权读取、合并或覆盖 Hermes、DSH 的私人记忆。
- 任务系统应记录任务来源、执行者、状态、结果与失败原因；审查与授权事件应可追溯。具体格式**待设计**。
- 文档、日志与报告不得记录 API Key、密码、令牌及其他秘密。日志收集范围、保留期限和脱敏规则**待确认**。
- Observer 的访问只限于获授权的任务状态、日志和报告；具体技术隔离**待设计**。

## 身份与权限原则（2026-11-07 设计稿，未实现）

完整设计见 [IDENTITY_AND_ACCESS.md](IDENTITY_AND_ACCESS.md)，默认权限见 [PERMISSION_MATRIX.md](PERMISSION_MATRIX.md)。以下是不可妥协的部分：

1. **双层边界原则**：Bridge 只做准入与审计，Agent 自己的工具策略做动作级拦截，真正的隔离靠 OS 账号/ACL。**不得把 Bridge 的 RBAC 宣传成安全边界**——三个 Agent 当前同用户运行，彼此文件互不可防。
2. **不把 ACP 握手当认证**：`initialize` / `authenticate` 只说明「该 Agent 有没有凭据」，不说明「谁在调用」。任何「ACP 已握手所以可信」的推论都无效。
3. **Bridge 不得自动批准权限请求**：`session/request_permission` 默认转人工或拒绝；**禁止**自动回 `allow_always`。自动批准等于拆掉唯一的运行时闸门。
4. **凭据身份与 Agent 身份分离**：审计必须记 `credential_ref`（只有名字，没有值）；共享凭据要显式标注。任何 Agent 不得使用他人的凭据或预算。
5. **硬禁止不可被 Agent 授予**：读他人私人记忆/会话/凭据、改策略与预算、代替用户授权、再委派财务/对外/管理类权限、未批准对外发言、无上限自主循环。清单见 PERMISSION_MATRIX §8。
6. **默认拒绝 + deny 优先 + 到期失效**：没写进策略的一律拒绝；任何一层 deny 全链拒绝；授权必须带 TTL，撤销通过 `policy_epoch` 递增。
7. **审计不可静默改写**：任务与授权事件写 append-only 日志，逐行带前一条哈希。发现问题时先保全证据，再修。
8. **状态不明不重放**：断线后任务进入 `unknown_execution`，由用户裁决；禁止「反正没回执就再跑一次」——那会重复执行、重复计费。
9. **闲聊不落记忆**：Lounge 消息默认不写长期记忆、不进决策；要写必须用户显式同意。

**三条落地细节（Observer 2026-11-07 审查补充）**

10. **审计防篡改的机制不能只靠「append-only 约定」，也不能只靠 ACL 位，更不能只靠"两个目录名"**（2026-11-08 二次修订）：
    - **主体必须分离**：`pae-hermes` / `pae-dsh`（对审计连读都没有）→ `pae-recorder`（对明细只有 `R,AD`）→ `pae-anchor`（对锚点只有 `R,AD`，对明细只读）。**两个审计主体都是独立必需账户，不允许与用户同权**（D-012）；Recorder 与 Anchor 若同进程同账号，等于没有锚点——攻陷 Recorder 就能同时改两边。
    - **追加权为什么成立**（不是约定）：追加只需 `FILE_APPEND_DATA`（`AD`）；偏移写与截断要 `FILE_WRITE_DATA`（`WD`）；删除要 `DELETE`；改名/替换要目标上的 `DELETE`；改权限/所有者要 `WRITE_DAC`/`WRITE_OWNER`。这四类都没给，所以是"只能读、只能往末尾写"的身份——可被 A1–A7 实测证伪。
    - **目录侧也要收紧**：`audit` 目录本身不给 Recorder `AD`（否则它能自造文件）。**注意 `(OI)(AD)` 不够**——不带 `(IO)` 时该 ACE 仍作用于目录自身（目录的 `AD` = 建文件）；必须写成 `(OI)(IO)(AD)`（`(IO)`= 仅继承，`icacls /?` 原文：「(IO) - 仅继承」）。段文件由用户侧任务预建，授权后对段文件执行 `/reset` 让继承生效。
    - **权限三分**：读取（用户 / Observer）、写入（Recorder 追加明细、Anchor 追加 checkpoint）、管理（仅用户）。任何执行账号对 `audit` 与 `audit-anchor` 都应**连读都没有**。
    - **写失败即停**：Recorder 启动自检（写 probe + fsync + 回读）不过 → 不 ready；Bridge 准入前查 `{ready,last_seq,lag}`，不 ready 就 **503 拒绝新任务**，在途任务 `session/cancel` 并标 `unknown_execution`。不允许"先干活后补账"。
    - **可检测性来自三方比对**：Observer 只读地重算链 + 核对 anchor 的 `(seq,hash)` + 检查各 Agent 的 `seq_local` 是否跳号。它不依赖 Recorder 的任何自述。
    - **仍必须照实写三条**：①这不是"不可篡改"，只是"篡改必留断点"；②**拿到管理员权限的一方仍然可以改写一切**——审计抬高的是门槛与可发现性，不是防住最高权限；③**Recorder 本来就有追加权，因此可以追加伪造事件**，ACL 层无解，只能靠 HMAC + 事件编号 + Observer 交叉核对发现异常（未实现）。
    - 设计细节见 [MVP §5.2](MVP_IDENTITY_AND_POLICY.md) 与 [W-1 v4 §6](reports/2026-11-08-w1-account-poc-plan-v4.md)。
11. **路径授权必须规范化后再比较**：`resolve()` 真实路径 → 统一大小写 → 拒绝 UNC（`\\?\`、`\\server\`）与 8.3 短名 → 按路径分隔符边界做前缀匹配（`reports\` 不能命中 `reports2\`）→ 对符号链接/junction 要么拒绝，要么「解析后校验目标仍在授权根内」。
12. **HMAC 只证明密钥持有者**：它证明「这条消息出自持有该密钥的进程」，不证明「这个操作是安全的」。被提示注入的 Agent 同样能签出合法消息。签名解决「是谁」，策略层解决「该不该」，两者不可互相替代。

13. **预算四层同时生效、取最严、互不抵消**（D-009 第 4 条）：
    - 四层＝一次性实验池 / 单次任务 / 每日 / 每月（外加 scope 内的 `per_run` 与 DSH 的更低单次上限）。
    - 判定式：`允许 ⟺ est ≤ min(单次上限, 日剩余, 月剩余, 池剩余, scope 内 per_run)`。
    - **禁止任何形式的抵消**：不能用「月余额还多」去放宽单次上限，也不能用「实验池没用完」去突破日上限。任一层不足即拒绝或转 `per_use` 审批。
    - 每次调用前重算，不缓存判定结果；任务结束写账本并回报剩余。

14. **本地预算估算 ≠ Provider 硬限制**（必须分开表述）：
    - 本地的 `$0.10 / $0.50 / $5 / $1` 是 **Bridge 侧估算 + 墙钟终止 + `session/cancel`（必要时杀进程）** 的组合，属于「软限额 + 硬停止」。
    - Provider 侧真正存在的硬边界只有**账户余额**与**套餐周窗口**（Codex）——它们不按任务切分，也无法被本地预算改变。
    - 因此**不得**在文档、UI 或对外描述里写「provider 保证不超过 \$0.10」。正确写法是「本地超过 \$0.10 会停止这次任务，但 provider 侧仍可能已产生少量费用」。
