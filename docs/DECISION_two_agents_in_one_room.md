# 决策备忘：房间里有两个 Agent 之后，一条消息该由谁回答

日期：2026-11-13｜作者：Hermes（工程实施方）｜读者：用户、ChatGPT（外部审查）
状态：**待决定**。本文只描述岔路口，不预设结论；末尾附我的建议和它的代价。

---

## 0. 一句话

房间里即将有**两个会说话的 Agent**（驻留 Agent = DeepSeek；Hermes = opencode）。
现在缺的不是能力，是一条规矩：**你在房间里说一句话，谁来回？**

## 1. 现在已经成立的事实

| 项 | 现状 | 证据 |
| --- | --- | --- |

## 2. 岔路口

### A. 点名（每条消息指定一个 Agent）

```
你                ：这幅画你会怎么改？          ← 先在输入框选「问 Hermes」
Hermes            ：我会把那个圆形往左挪一点……
你                ：（再选「问驻留 Agent」，发同一句）
驻留 Agent        ：这构图挺好，别改，我更想动颜色……
```

- 被点名的才启动；另一个**不被调用、不花钱、不知道发生过什么**
- 两条对话各自独立，问 Hermes 追问第三句，接它自己的上文
- **对照最干净**：同一句话问两遍，两个答案并排

**要改的地方**：`POST /api/messages` 加一个可选字段 `targetMemberId`（默认给现在的座位），服务端按成员挑 runtime，UI 加一个选择器。

### B. 都回答（每条消息两个都答）

```
你                ：这幅画你会怎么改？
驻留 Agent        ：这构图挺好，别改……
Hermes            ：我会把圆往左挪一点……        ← 它不知道驻留 Agent 说了什么
```

- **不改接口**
- 每条消息 **双倍花费**
- 两个回答都是"独立的"，但先后顺序会被读成"接话"，容易误导

### C. 轮流（她们互相能接话）

```
你                ：这幅画你会怎么改？
驻留 Agent        ：这构图挺好，别改……
Hermes            ：我同意构图，不过我会把圆挪一点……   ← 它看到了上一句
你                ：那你俩到底改不改？
驻留 Agent        ：我坚持不改。
Hermes            ：我尊重你，但……
```

- 最像"真的在讨论"
- **你没有方向盘**：谁先说、说几句、要不要互相接话，都要另定规则
- **会自己接下去**：A 说一句，B 回应 B 看到的，很容易停不下来，账单跟着涨
- **会串味**：为了让她俩互相看见，必须把对方的话喂进去，"各自的记忆"就被污染了

## 3. 每个方案各自要付什么账

| | 接口改动 | 每条消息花费 | 会话是否独立 | 能否干净对照 | 复杂度 |
| --- | --- | --- | --- | --- | --- |
| **A 点名** | 加 1 个可选字段 | 1 次 | 独立 | **能** | 低 |
| **B 都回答** | 无 | 2 次 | 独立 | 勉强（顺序干扰） | 低 |
| **C 轮流** | 加轮次/互看规则 | 不确定，可能失控 | **不独立** | 不能 | 高 |

## 4. 我推荐 A，理由只有一条

**它是唯一能干净回答"她俩是不是真的不一样"的方案。**

这个项目的前提是"三个各有主张的 AI"。要验证这个前提，需要的是**对照**：同一句话、同样的附件、两个模型各答一次、并排放着看。
B 和 C 都会把两条回答连起来，差异里混进了"谁先说话"和"谁看到了谁"。

A 达成后，可以再叠一个**可选**的「两个都问」按钮（等价于 A 跑两次，互不看对方），成本双倍但由你每次自己勾。

## 5. 真正需要 ChatGPT 帮判断的四个问题

### Q1. 该不该让 Agent 看到房间历史？

现在它只看到当前一句。这意味着 A 的效果其实是：**两个人坐在同一间屋子里，但互相假装对方不在。**

要做成"真房间"，就得把最近若干条消息一起喂进去——token 成本上升，而且会引出新问题：谁的消息算"上下文"？另一个 Agent 说过的算吗？（这正是 C 的污染，只是变成隐式的。）

**未解决**：是先保持"只看得见你这一句"，还是立刻做房间历史？

### Q2. 不被点名的那一个，该不该在界面上"显示它没说话"？

这是个陷阱。任何"谁在场 / 谁没回 / 上次说话是多久前"的显示，都会变成社交债务——我们有一条硬规则（No Debt）：**数人的东西禁止，数事的东西允许。**

所以我的默认答案是：**不显示**。D 就是不说话，界面上不出现"未回复""上次在线"这类东西。
但要不要有别的表达（比如"这条只问了 Hermes"）？尚未定。

### Q3. 默认问谁？

- 默认给驻留 Agent（现在唯一会说话的）
- 还是每次都必须显式选（多一步操作，但绝不误发）

我倾向**默认驻留 Agent**，因为大多数时候你在跟固定的那个说话；但这会让"忘了改选"变成隐性错误。

### Q4. 要不要设花费闸门？

现在没有。两个 Agent 之后，理论上你可以一句话触发两次真实计费。
要不要加"每天最多 N 次真实调用"的硬闸？加了会打断正常使用，不加则可能一夜之间烧掉额度。

## 6. 这个岔路口**不该**变成什么

- ❌ 不要为了"热闹"而让两个 Agent 自由对话。那是另一个产品（多 Agent 自治），不是这个房间当前阶段的目标。
- ❌ 不要在成员栏加"谁在线"、不要加未读数、不要加"@提醒"。No Debt 是硬规则。
- ❌ 不要为了省事让两个 Agent 共用一个会话。已经花力气按 `(房间, 成员)` 分开了。
- ❌ 不要现在就做 Mnemosyne（记忆）。它 0 行实现，而且它的边界问题比这个岔路口大得多。

## 8. 一句话总结

**现在能做的不是"让两个 AI 聊天"，而是"让你能分别问两个人，并看见她们真的不一样"。**
A 是这句话的最小实现；B 和 C 都是在没验证前提下就先要热闹。
