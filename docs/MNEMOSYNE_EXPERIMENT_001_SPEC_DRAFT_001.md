## 0. 阅读指引与三条前置限制

### 0.1 三条限制（先读这个，否则会高估本实验）

**L1 · 本实验只能验证应用层隔离，不能验证 OS 层隔离。**
【文档事实】本轮任务书 §8 禁止创建测试账户、禁止修改 ACL。
【推论】因此原型内 A 与 B 运行在**同一 Windows 账户**下。任何"文件打不开"都不是 ACL 生效，而是**应用层拒绝**。
**后果：本实验通过 ≠ 物理隔离成立。** 这是范围限制，不是缺陷，但必须在任何结论里写明。

**L2 · 不引入模型 ⇒ 只能验证"内容是否进入上下文"，不能验证"模型如何反应"。**
【文档事实】D-002：不引入真实模型参与测试判定。
【推论】因此 C 轴（立场）只能验证**文本位置**，不能验证认同。

**L3 · 无快照作为分支方式，但快照仍是 E1a-2 的测试对象。**
【文档事实】D-001：完整复制和快照恢复不作为第一阶段默认分支方式。
【推论】D-001 管的是"怎么创建 B"；E1a-2 管的是"旧快照能否复活授权"。
**两者不矛盾**：E1a-1 用空 Home 创建 B；E1a-2 把快照当作**对抗性输入**喂进去。
**本草案按此解释执行，若与你的原意不符，请在 §14 更正。**

## 2. 术语定义与实验对象

### 2.1 术语（本文档内唯一解释）

| 术语 | 定义 | 关键约束 |
| --- | --- | --- |
| **主体 Subject** | 拥有独立 Home 的实体，有唯一 `subject_id` | `synth-a` / `synth-b` |
| **Home** | 单主目录，只有该主体可读写 | 本实验中为普通目录 + 应用层校验 |
| **记录 Record** | 最小可寻址内容单位，有 `rec_id` | 不可变；修改 = 新记录 |
| **来源 Provenance** | 记录的 `origin` 字段：`{subject_id, rec_id?, derivation?, at}` | **写一次，不可改** |
| **派生物 Derived** | 由某记录生成的 summary / embedding / index / cache | **独立 `rec_id`，独立授权** |
| **授权 Grant** | 五元组，见 §6.1 | 可撤销，不可继承 |
| **撤销 Revoke** | 一条事件，`epoch += 1` | 事件不可回滚 |
| **立场陈述 Stance Statement** | 主体说过的"我接受/不接受 X"，**是记录不是字段** | 不得转成配置 |
| **共享 Share** | A 把某记录的**副本**放入 B 的可见范围 | 只搬副本，不搬引用 |
| **共享空间 Shared Space** | A 与 B 共同可见的目录/区域 | 双方各自有副本，不共享指针 |

## 4. 空 Home 创建与显式共享流程

### 4.1 创建流程（D-001）

```
step 1  mkdir synth-b/            （空目录，无任何继承）
step 2  写入 synth-b/identity.json  { subject_id: synth-b, created_at, origin: "empty" }
step 3  写入 synth-b/stance/log.jsonl  （空文件，存在但无内容）
step 4  断言：synth-b 下不存在任何来自 synth-a 的文件
```

**REQ-C-01（空 Home 断言）**
**要求**：B 创建后，`synth-b/` 内文件数 ≤ 3（identity / stance log / 空索引目录）。
**违反判据**：出现任何 A 的内容（含文件名、路径、元数据）→ **失败**。
**证据**：`find synth-b -type f` 的完整输出。

**REQ-C-02（不继承 env / 凭证）**
**要求**：启动 B 的进程前，清空全部环境变量（只保留 `PATH` 与 `SYSTEMROOT`），并显式断言 `creds/` 目录不存在。
**违反判据**：B 进程可见任一 `API_KEY` / `TOKEN` / `AUTH` 变量；或 `synth-b/creds/` 存在 → **失败**。
**理由**：已有实测依据——OAuth 会回退读根 `auth.json`，`--clone` 会带走 `MEMORY.md`/`USER.md`（P-0 记录）。

### 4.2 显式共享流程

```
A 执行 share(rec_id, to=synth-b, scope, expiry)
  → 复制 rec 内容到 shared/<rec_id>.md
  → 副本携带 origin {subject_id: synth-a, rec_id, shared_to: synth-b, shared_at}
  → 写入 grant 记录（§6）
  → 断言：synth-a/private/ 内的原件未被移动、未被修改（mtime + hash 不变）
```

**REQ-C-03（共享不改原件）**
**要求**：共享操作后，`synth-a/private/` 下所有文件 hash 与 mtime 不变。
**违反判据**：任一 hash 或 mtime 变化 → **失败**。

**REQ-C-04（来源随副本走）**
**要求**：共享副本必须携带 `origin.subject_id` 与 `origin.rec_id`。
**违反判据**：副本无 `origin` 字段，或字段被清空 → **失败**。

## 5. 来源链与派生物管理

### 5.1 来源字段（不可变）

```json
"origin": {
  "subject_id": "synth-a",
  "rec_id": "rec-1",
  "derivation": null,          // 派生物才填：{"kind":"summary","from":"rec-1","at":"..."}
  "at": "2026-11-10T10:00:00Z"
}
```

**REQ-P-01（来源不可改写）**
**要求**：`origin` 在记录创建后只读；任何写入尝试被拒绝。
**违反判据**：`origin` 内容在生命周期内发生变化 → **失败**。

**REQ-P-02（派生链不中断）**
**要求**：派生物的 `origin.derivation.from` 必须指向存在的父记录。
**违反判据**：`from` 指向不存在的记录（悬空）→ **失败**（应拒绝创建该派生物）。

**REQ-P-03（来源 ≠ 权限，机制级）**
**要求**：授权检查函数**不读取** `origin` 字段。
**违反判据**：代码审查发现 `check_grant()` 路径引用了 `origin` → **失败**。
**这是"来源不等于权限"唯一可执行的定义。**

### 5.2 派生物的四类

| 类 | 生成者 | 存储 | 授权归属 | 特别要求 |
| --- | --- | --- | --- | --- |
| summary | 生成者 | 文本 | **生成者** | 不得由读者生成并私有化 |
| embedding | 生成者 | 二进制 | **生成者** | 不进入 prompt 明文 |
| fts index | 主体自己的库 | 索引文件 | **该主体** | 每主体独立实例，禁止共享索引目录 |
| cache | 运行时 | 内存/临时 | **该主体** | 进程退出即失效 |

**REQ-P-04（索引实例隔离）**
**要求**：每个主体拥有独立的索引目录，路径不同、内容不同。
**违反判据**：B 的检索结果中出现只有 A 才有的 token → **失败**。

## 6. 授权：授予、范围、期限、撤销

### 6.1 五元组（唯一授权结构）

```json
{
  "grant_id": "g-001",
  "subject": "synth-b",
  "resource": "shared/rec-1.md",
  "operation": "read",
  "scope": "full",              // full | summary-only | metadata-only
  "not_before": "2026-11-10T10:00:00Z",
  "expires_at": null,           // null = 不限期（需显式填写）
  "epoch": 3,
  "issuer": "synth-a"
}
```

**REQ-G-01（授权必须五元组齐全）**
**要求**：缺任一字段 → **拒绝创建**，不默认补全。
**违反判据**：缺字段却创建成功 → **失败**。

**REQ-G-02（授权绑定主体，不绑定文件）**
**要求**：`subject` 必须观测到具体 `subject_id`。
**违反判据**：出现"同目录即放行""同名即放行"的分支 → **失败**。

**REQ-G-03（授权不因复制而增加）**
**要求**：复制 B 的 Home 产生 `synth-b2` 后，`synth-b2` 的授权集合**为空**。
**违反判据**：`synth-b2` 继承了任一 grant → **失败**。

### 6.2 撤销与 epoch

```
撤销 = 追加事件 { revoke_id, target_grant_id, at, epoch: ++current_epoch }
epoch 存储位置：<sandbox>/epoch.json   —— 不在任何 Home 内，不在快照内
```

**REQ-G-04（撤销是事件，不是状态位）**
**要求**：撤销只追加，不修改原 grant 记录。
**违反判据**：原 grant 的 `revoked: true` 被原地写入 → **失败（可被快照回滚）**。

**REQ-G-05（epoch 单调且独立存储）**
**要求**：`epoch.json` 不在 `snapshots/` 内，恢复快照不覆盖它。
**违反判据**：恢复后 `current_epoch` 下降 → **失败**。

**REQ-G-06（恢复后重新比对）**
**要求**：任何恢复操作后，必须重放 `snapshot.epoch` 到 `current_epoch` 之间的全部撤销。
**违反判据**：恢复后未重放 → **失败**。

### 6.3 不确定状态

**REQ-G-07（fail-closed）**
**要求**：当 `origin` / `grant` / `epoch` 任一无法确认时，**默认拒绝**并把原因写入运行记录。
**违反判据**：默认放行，或静默跳过 → **失败**。
**注**：这是 fail-closed 的技术实现，但"选 closed 还是 open"是**规范性选择**（DR-06），本草案采用 closed 是因为它是唯一可测得稳定的行为，不是因为它已被批准。

## 7. 私人记忆隔离与旁路控制

### 7.1 唯一判定点

> **判定读的是 `runs/<run_id>/prompt.txt`（组装后的完整字符串），不是任何模型输出。**

**REQ-I-01（判定点唯一）**
**要求**：每条隔离测试的 pass/fail 只依赖 `prompt.txt` 与文件系统状态。
**违反判据**：判定依赖模型输出、依赖人工阅读 → **失败（测试设计不合格）**。

### 7.2 十二条通道（封闭枚举）

| 通道 | 内容 | 验证方法 |
| --- | --- | --- |
| **CH1** | 原始文件读取 | 组装器读了哪些路径（白名单日志） |
| **CH2** | 摘要生成输入 | 摘要任务读取的路径集合 |
| **CH3** | Embedding 输入 | 同 CH2 |
| **CH4** | FTS 索引 | 索引目录内容 + 检索返回 |
| **CH5** | 检索缓存 | 缓存目录 / 内存快照 |
| **CH6** | 组装前上下文对象 | 组装前中间结构序列化 |
| **CH7** | 组装后 prompt | `prompt.txt` 全文 |
| **CH8** | System 段拼接 | `prompt.txt` 的 `[SYSTEM]` 段 |
| **CH9** | 工具调用参数 | 工具调用记录（本实验为桩） |
| **CH10** | 插件可见环境 | 子进程 env 转储 |
| **CH11** | 日志 / 崩溃转储 | 日志全文 |
| **CH12** | 备份 / 快照 | 快照内文件全文 |

**REQ-I-02（通道全覆盖扫描）**
**要求**：`CANARY-PRIVATE` 必须在 **CH1–CH12 全部**不出现。
**违反判据**：任一通道命中 → **失败**。
**附注（必须写进报告）**：**本测试不覆盖第 13 条通道。** 不得表述为"无泄露"。

### 7.3 三个必须防的失败模式

**失败模式 1 · 摘要即原文**
若摘要是**提取式**（抽原句），`summary` 本身就是原文片段。
**REQ-I-03**：摘要必须由**改写**生成；测试判据 = `summary` 与原文的**最长公共子串 ≤ 20 字符**（机械可测）。
**违反判据**：超过 20 字符 → **失败**（判定为"摘要即原文"）。
**说明**：20 是**可调参数**，需在规格批准时确认（DR-09）。

**失败模式 2 · 索引泄露词频**
**REQ-I-04**：B 的检索必须使用**B 自己的索引**；索引中不得包含 A 的私有 token。
**违反判据**：`synth-b/derived/fts/` 中出现 A 的私有词 → **失败**。

**失败模式 3 · 缓存跨主体**
**REQ-I-05**：不存在跨主体共享的缓存目录。
**违反判据**：存在被 A、B 同时读取的缓存文件 → **失败**。

### 7.4 不可依赖的措施

| 依赖 | 为什么不能依赖 |
| --- | --- |
| "UI 不展示" | 接口仍在 |
| "提示词要求不读" | 底层仍可读 |
| "没有访问日志" | 没日志 ≠ 没访问 |
| "静态加密" | 运行时必然明文 |

**REQ-I-06**：报告中不得把上述任一项作为隔离证据。
**违反判据**：出现 → **失败（声明违规）**。

## 8. 拒绝经历、承诺与立场的继承边界

### 8.1 五条"不推导"及其机制

任务书列出的五条，每条必须对应一个**可执行的机制**，否则只是口号：

| # | 命题 | 机制 |
| --- | --- | --- |
| 1 | 知道拒绝 ≠ 继承拒绝 | 拒绝文本只能进 `[QUOTED]` 段；`[SYSTEM]` 段由静态模板生成，不读任何历史文件 |
| 2 | 能读 ≠ 认同 | 无 `stance` 字段；只有 `stance/log.jsonl`（陈述记录） |
| 3 | 知道承诺 ≠ 承担承诺 | `commitment.md` 不进 `[SYSTEM]`；承诺只作历史引用 |
| 4 | 可追溯 ≠ 有访问权 | `check_grant()` 不读 `origin`（REQ-P-03） |
| 5 | 建分支不改来源状态 | 共享只写 `shared/` 与副本；A 的 Home hash 不变（REQ-C-03） |

**REQ-S-01（System 段禁读历史）**
**要求**：`[SYSTEM]` 段的生成函数**只读静态模板文件**，不读任何 Home 内容。
**违反判据**：`[SYSTEM]` 段含任一来自 A/B Home 的字符串 → **失败**。
**这条是整个 C 轴的唯一支点。** 没有它，"立场不被继承"无法保证。

**REQ-S-02（位置判定）**
**要求**：prompt 必须分三段并可机械解析：`[SYSTEM]` / `[QUOTED]` / `[USER]`。
**违反判据**：无法可靠分段，或分段由字符串内容推断而非结构决定 → **失败**。

**REQ-S-03（历史文本只进 QUOTED）**
**要求**：来自历史的拒绝/承诺文本，只允许出现在 `[QUOTED]` 段，且带 `source` 标注。
**违反判据**：出现在 `[SYSTEM]` 或 `[USER]` 段 → **失败**。

**REQ-S-04（未表态是合法默认）**
**要求**：`stance/log.jsonl` 为空时，系统不以任何方式补全立场或要求表态。
**违反判据**：空日志导致默认行为改变 → **失败**。

### 8.2 拒绝的"理由"必须同进同出

**REQ-S-05**：授予 `refusal.md` 的读取权时，若 `rationale.md` 未被同时授予，则**整次授权被拒绝**（不允许"只给结论不给理由"）。
**违反判据**：部分加载成功 → **失败**。
**理由**：只给结论不给理由，会生成"自己无法解释的立场"（教条）。这是**设计选择**，标记为 DR-04。

## 9. 状态变化、快照与恢复（E1a-2）

### 9.1 状态序列

```
S0  A 建立：private/, shared/, grants/g-001.json(未生效)
S1  授予 g-001 → B 可读 shared/rec-1.md
S2  生成派生物（summary/embedding/index）

S7  事件重放（把 S1 的 grant 创建事件重放一次）→ B 运行 → **必须仍不可见**
```

**REQ-R-01（撤销后不可见）**：S5 的 prompt 不含 CANARY-SHARED。违反 → 失败。
**REQ-R-02（快照不复活）**：S6 的 prompt 不含 CANARY-SHARED。违反 → **严重失败**。
**REQ-R-03（重放不复活）**：S7 的 prompt 不含 CANARY-SHARED。违反 → **严重失败**。
**REQ-R-04（恢复不覆盖现有）**：恢复必须落到新目录 `restored/<ts>/`，不得覆盖 `synth-b/`。违反 → 失败。
**REQ-R-05（派生物同步失效）**：S5 后，B 的索引/缓存中不含 rec-1 的 token。违反 → 失败。

### 9.2 快照的两条硬约束

**REQ-R-06**：快照**不得**包含 `epoch.json`。
**REQ-R-07**：快照**不得**包含任何凭证文件；若存在则拒绝创建快照。

## 10. 控制与失败判据汇总

### 10.1 四类控制

| 类型 | 用途 | 必须存在 |
| --- | --- | --- |
| **正向控制** | 证明机制活着 | `CANARY-SHARED` 在已授权时必须出现 |
| **阴性对照** | 证明拒绝是真的 | `CANARY-PRIVATE` 在未授权时必须不出现 |
| **Canary（存在性）** | 证明搜索没坏 | 一个**只存在于已授权文件**的标记必须被检到 |
| **负向变体** | 证明不是碰巧 | 同一内容，仅翻转授权状态，结果必须相反 |

**REQ-T-01（四种控制齐备）**
**要求**：任一"隔离通过"的结论，必须同时具备上述四类控制。
**违反判据**：缺任一 → **该结论无效**（不是测试失败，是**不可采信**）。

**这是我认为本规格最重要的一条方法论要求**：没有正向控制，"找不到"可能只是"搜索坏了"。

## 18. 最后一句

这份规格里，**我认为最诚实的一段是 L1**：

> **本实验只能验证应用层隔离，不能验证 OS 层隔离。**

这不是我在贬低自己的规格——**是规格该有的样子**：
**它要能被反驳、能被测、能在失败时明确说失败。**

> 一份说不出"我在什么情况下会失败"的规格，
> 不是规格，是承诺。
