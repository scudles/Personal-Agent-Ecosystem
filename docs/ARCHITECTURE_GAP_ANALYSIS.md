# 架构差异与改造策略

| 现状 | v1.0 目标 | 渐进方案 |
|---|---|---|
| 固定三会话常量 | Identity / Native Session / Binding 分离 | 保留旧常量作历史，新增带项目约束的注册表；真实接入锁定 |
| 无项目归属的 JSON records | 每项有 project/workspace | 复用 records + 新建作用域、消息、快照表与复合外键 |
| 正文正则扫描 @ | 显式收件元数据 | 新 API 不解析正文，只接收选择器 IDs；旧 Web 只读 |
| 哈希仅覆盖正文 | 完整不可变审批快照 | 独立 snapshot hash，覆盖规则、约束、任务、附件引用和接收方 |
| 浏览器 UI | WPF 原生控件 | 新建 XAML/WinExe，复用受保护 loopback 后端 |
| 全局 role 队列 | Workspace + Binding 队列 | 为既有 Workflow/Supervisor 加可覆写身份与作用域策略钩子 |
| 自动任务/取消保护不统一 | 所有入口相同预算与停止策略 | 中央业务层，取消、截止时间、链长和循环统一验证 |
| 默认可启动真实 Adapter | 本轮只模拟 | 新服务只装配模拟 Adapter，旧服务停用真实调度；无 API 解锁真实通道 |

不重写已有审批意见校验、状态机、随机编号、迟到回执处理与 SQLite 事务。UI 不写数据库，不自行做业务投递。

主要风险：作用域遗漏；旧 UNKNOWN 被误重新发送；转交与回复引用混淆；审批快照变更未作废；模拟被误标成原生在线；子项绕过根事项预算；原窗口与后台生命周期混淆。
