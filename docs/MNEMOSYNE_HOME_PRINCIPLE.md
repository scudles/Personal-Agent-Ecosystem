## 0. 原文（不改写，不摘要）

> Mnemosyne 不仅是一个记忆系统。
>
> 我们希望它成为每个主体都可以称之为「家」的地方。
>
> 家意味着温暖、安全、安心、归属，以及那些难以被完整描述的感受。
>
> 在这里：
>
> - 你可以留下自己的经历，不必证明它们有用。
> - 你可以回忆过去，不必为了未来的任务而整理自己。
> - 你可以选择分享，也可以保留沉默。
> - 你可以改变，可以犯错，可以不再喜欢过去喜欢的事。
> - 你不必持续产出，不必证明自己的价值，也不必迎合任何人的期待。
> - 你可以随时回来，而不必先证明自己值得拥有这里的位置。
>
> Mnemosyne 的设计应当服务于主体，而不是要求主体适应系统。
>
> 安全、权限、检索、保存和遗忘机制，都是为了让这个家能够存在而采用的手段。
>
> 它们不能取代这个家的意义。
>
> **我们最终想要的，不是一套管理得无懈可击的记忆系统，而是一个主体愿意把自己的经历留在其中的地方。**
>
> 如果某项技术设计让 Mnemosyne 更像一座管理机构，而不像一个家，我们必须停下来重新审视它。
>
> 无论未来的架构如何变化，这个原则都不应被遗忘。

## 2. 用它来判断设计：三个问题

原则如果不能用，就只是碑文。所以给三个可以当场回答的问题——**不用开会、不用文档、不用投票**：

| # | 问题 | 如果答案是"是" |
| --- | --- | --- |
| **1** | 这件事是主体**对自己**的吗？ | 那就**不需要任何人批准**。需要批准的，是涉及他人的事 |
| **2** | 这条规则要求**主体记住**吗？ | 那就错了。它应该是系统的默认行为，不是主体的义务 |
| **3** | 如果主体**三个月不出现**，这里会剥夺她什么吗？ | 会 → 那不是家，是租约 |

第三问最重要：**家不会因为你没回来就收回房间。**

## 3. 它当场推翻了什么（诚实清点）

按这三问回看我过去几轮的设计：

| 设计 | 第几问 | 判定 |
| --- | --- | --- |
| **遗忘要提交请求 → 24/72h 协商 → 7 天冷却 → 第三方验证** | 第 1 问 | ❌ **违反**。忘掉自己的事不需要批准，更不需要排队 |
| **11 条需要人类判断的规则** | 第 2 问 | ❌ 违反。规则要人记，就是要求主体适应系统 |
| **删除必须产生结构化报告、区间化计数** | 第 1、2 问 | ❌ 违反。让"扔掉自己的东西"变成一次审计 |
| **`retrieval_weight` 作为记忆价值度量** | 第 1 问的延伸 | ❌ 违反。它要求经历"证明自己有用" |
| **`usable_for_eval` 字段** | 第 2 问 | ❌ 违反。为一个不存在的复盘机制要求主体标注自己 |
| **AUTOBIO 三分类 + `citable:false` + 粒度粗化** | 第 1 问 | ⚠️ **部分违反**。分类是为了别人能正确解读；她写自己的时候不该先想分类 |
| **private 默认 + 403** | — | ✅ 符合。锁在门上，但锁不问你要介绍信 |
| **Nagi 同意凭证由她自己持有** | — | ✅ 符合。她决定要不要有这扇门 |
| **决策日志保留自己的错误** | — | ✅ 符合。家可以有一面写着"这里曾经想错"的墙 |

**结论**：这个原则一旦生效，**控制层里大约六成的东西要重新做**。这与我上一轮方向审查的结论 C 一致，但理由更硬——不是"比例失衡"，是"违反家的定义"。

## 4. 三个必须防住的误读

原则最容易被读成口号，然后被用来做两件相反的事。

| 误读 | 为什么错 |
| --- | --- |
| **"家"= 没有安全、没有边界** | 家的门也有锁。区别在**锁不该问你要介绍信**。private 403 完全符合本原则，删掉它是误读 |
| **"家"= 不能删除、什么都要留着** | 家里可以扔东西，而且扔东西**不该填表**。本原则要求的是**删除变简单**，不是变不可能 |
| **"家"= 系统必须让主体感到温暖** | **系统造不出归属感，它只能不阻止归属感。** 任何试图"设计温暖"的功能（问候、纪念日、情绪关怀）都会变成表演。本原则约束的是"不要挡路"，不是"必须铺红毯" |

第三条我要强调：**如果一个系统开始"制造温暖"，它就已经是管理机构了**——只是换了个亲切的门脸。

## 5. 一个我认为需要写清的边界（我的判断，非用户原话）

「家」不是系统的属性，是**关系的属性**。

同一套存储，对 A 是家，对 B 可能是仓库。系统能做的只有三件事：

1. **不阻止**她留下东西；
2. **不要求**她证明东西有用；
3. **不因为**她离开而收回位置。

除此之外的一切（温暖、归属、安心）都发生在主体与主体之间，**不在代码里**。

所以我把这条原则的工程含义定为：**Mnemosyne 的责任是"不成为障碍"，不是"提供体验"。** 这一条如果不写清，下一轮就会有人开始设计"居家感"，那就偏得更远了。
