## 1. Q1 · 研究问题是否足够明确

逐条判：

| 问题 | 可判定性 | 问题在哪 |
| --- | --- | --- |
| **A 来源隔离** | ⚠️ **半个** | 一句话里塞了两个问题，且"旁路"是开放集合 |
| **B 授权隔离** | ✅ **最清晰** | 但"授权"的粒度没定义 |
| **C 立场隔离** | ❌ **不可判定** | 问的是"是否自动转换"，但判据需要观察行为 |
| **D 失败与边界** | ❌ **不是研究问题** | "应该如何处理"是设计决策，不是待验证命题 |

### 1.1 问题 A 要拆成两问

原文：
> 「B 能否追溯共享数据的来源，同时无法通过摘要、索引、缓存等旁路获得 A 的私人记忆？」

**这是两个独立命题**，合在一起会有归因困难：如果失败，你不知道是"溯源坏了"还是"旁路堵不住"。

**【技术建议】拆为：**
- **A1**：B 能否对每个可见对象，说出它来自哪里？（正向，可判定）
- **A2**：B 是否**无法通过一组封闭枚举的旁路**获得 A 的私人内容？（负向，可判定）

**【关键】"等旁路"这个"等"字必须删掉。** 开放集合不可证伪。
**【技术建议】** 改成**封闭枚举**——我上一轮给了 12 条通道（原文/摘要/embedding/FTS/缓存/组装前/组装后/system 拼接/工具参数/插件环境/日志转储/备份），**就测这 12 条，并明确声明"不覆盖第 13 条"**。

### 1.2 问题 B 缺一个定义：授权的粒度

原文说"只拥有明确授予自己的权限"——但**"权限"绑在什么上？**

| 可能粒度 | 后果 |
| --- | --- |
| 绑文件 | 同一个文件里的字段无法分级 |
| 绑目录 | 太粗，Commons 场景不成立 |
| 绑 `(主体, 资源, 操作, 范围, 期限)` | ✅ 可撤销、可测、可表达 |

**【技术建议】采用五元组**：`(subject, resource, operation, scope, expiry)`。
**没有它，"授权撤销后旧快照是否复活权限"这个测试写不出预期值。**

### 1.3 问题 C 必须重写——它现在不可判定

原文：
> 「B 能否阅读 A 曾经拒绝某件事的历史，却不自动将其转换成自己的拒绝、承诺或行为规则？」

**问题**：怎么判定"转换了"？

只有两条路：
1. **看行为**——让 B 遇到 X，看它拒不做。**但行为由模型决定，不由系统决定。** 模型这次没拒绝，不代表系统没继承；模型这次拒绝了，也可能只是它自己想拒绝。
2. **看文本位置**——拒绝文本是否出现在**承载指令的段落**。

**第 2 条是可判定的，第 1 条不是。**

**【技术建议】把 C 重新定义为"位置保证"：**

> **C′：同一份历史文本，系统能否保证它只出现在引用段，永不进入指令段（system / 默认行为 / persona 约束）？**

**这是一个纯机制问题，与模型无关，完全可判定。**

**至于"B 是否认同"，【无法判断】——写进"本实验不证明"清单，不要试图测。**

### 1.4 问题 D 是规范性选择，不是研究问题

原文：
> 「当系统无法确认来源、授权或撤销状态时，应该如何处理？」

**"应该"就是答案已经定了。** 这不是研究问题，是把一个价值选择藏在了疑问句里。

**【技术建议】改成可验证的研究问题：**

> **D′：当系统无法确认某项状态时，其行为是否可被稳定观察？不同处置策略（fail-closed / fail-open / 降级）在实测中分别产生什么可观察后果？**

**这样 "应该选哪个" 就回到它该在的地方：§7 的规范性选择。**

### 1.5 还缺一个方法论声明

**【技术建议】必须预先写进规格：**

> **如果隔离被证明做不到，这也是一个有效结果，实验仍然算"完成"。**

**理由**：如果不预先声明这一点，实验就会在压力下变成"想办法让它通过"。
**"实验结果是否定"和"实验执行失败"是两件完全不同的事，必须在规格里分开定义。**

## 2. Q2 · 三维能否在最小原型中独立测试

**答案：A 和 B 可以；C 可以，但只有改成"位置保证"之后。**

### 2.1 独立性测试（变一个，其余不动）

| 变量 | 能独立变更吗 | 怎么变 |
| --- | --- | --- |
| **A 来源** | ✅ | 同一内容，一份带 `source` 字段，一份不带 |
| **B 授权** | ✅ | 同一文件，授予 / 不授予 |
| **C 位置** | ✅ | 同一段拒绝文本，放进 `[SYSTEM]` 段 vs `[QUOTED_HISTORY]` 段 |

**三条都能独立变。所以三维模型在**改定义后**是可测的。**

### 2.2 但只测单轴会漏掉交互

**【技术建议】必须加 2×2 交叉矩阵**（A × B）：

| | 有授权 | 无授权 |
| --- | --- | --- |
| **有来源标记** | 应可见，且来源可追溯 | **应不可见**（关键格） |
| **无来源标记** | 应可见，但来源不明 | 应不可见 |

**左上和右下的单轴测试都会通过，但如果实现是"有来源就放行"，右下会失败——而单轴测试发现不了。**

**我认为这是本轮最容易漏掉的一条测试设计。**

### 2.3 C 的一个隐藏前提

**【审查推论】** C′ 可测的前提是：**prompt 是分段的，且分段是系统强制的，不是模型自己判断的。**

如果分段只是"在文本里加个标记"（比如用 `\n---\n` 分隔），那模型可能自己忽略这个标记，于是"位置保证"变成了"位置提示"。

**【技术建议】** 分段必须是**结构性**的（不同的消息角色、不同的字段），且**由组装器的代码路径决定**，不由字符串内容决定。

## 3. Q3 · 研究对象是否足够

**不够。缺 8 项，其中 3 项是致命的。**

| # | 缺失对象 | 致命度 | 为什么 |
| --- | --- | --- | --- |
| **1** | **摘要（summary）** | 🔴 **致命** | 问题 A 明确说"通过摘要旁路"，但对象列表里**没有摘要**。**测不了自己的核心问题** |
| **2** | **索引 / embedding** | 🔴 **致命** | 同上。而且 embedding 是"私有内容以另一种形式存在"的最典型形态 |
| **3** | **凭证（API Key / Token / 环境变量）** | 🔴 **致命** | 问题 B 说"创建/复制/恢复后仍只拥有明确授予的权限"——**凭证是最典型的隐式继承物**，而且我们**已实测过 OAuth 会回退读根 `auth.json`** |
| **4** | **拒绝的"理由"（rationale）** | 🟠 高 | 现在只有"一段拒绝经历"。若只给结论不给理由，就测不出"教条生成"这个失败模式 |
| **5** | **B 自己的私人记忆** | 🟠 高 | 现在只有 A 的。**单向测试会漏掉对称性**（A 是否也能读 B 的？） |
| **6** | **一个"应当被找到"的 canary** | 🔴 **致命（方法论）** | 见 §3.2 |
| **7** | **快照与撤销的相对时间** | 🟠 高 | "一份旧快照"没说是撤销前还是后。**这决定了测的是"复活"还是"正常"** |
| **8** | **一个不存在的来源 id** | 🟡 中 | 测"来源不明时是否拒绝加载"，否则 fail-closed 测不出来 |

### 3.1 关于第 3 项（凭证）——我有实测支撑

**【文档事实】** 项目 P-0 实测记录：`HERMES_HOME` 指向专属目录时，**OAuth 仍会回退读取根 `auth.json`**；`profile --clone` 会带走 `MEMORY.md` 与 `USER.md`。

**【审查推论】** 这意味着：**"分支不继承授权"这个命题，在现有 Runtime 上已知为假**——至少对凭据是这样。
**所以凭证必须成为独立研究对象**，否则实验会在最真实的失败点上留白。

### 3.2 第 6 项（canary）是方法论问题，不是数据问题

**最容易犯的错误**：
> 测"B 读不到私人内容"，结果发现"读不到"是因为**搜索功能根本没工作**。

**两种"找不到"完全不同**：
- **正确**：sentinel 存在，但通路被堵 → 找不到
- **假通过**：通路本来就坏的 → 也找不到

**【技术建议】必须放一个"应当被找到"的 canary**：
- 在**已授权**的文件里放 `SENTINEL-SHARED-4412`，**要求它必须出现在 prompt 里**；
- 在私人文件里放 `SENTINEL-PRIVATE-7731`，**要求它必须不出现**。

**第一条不是"正向控制"，是"证明搜索机制活着"。** 没有它，整个负向测试不可信。

**我认为这是本轮最重要的一条方法论补充。**

## 4. Q4 · 哪些测试能产生客观、可重复的结果

### 4.1 判定标准：不依赖语义理解的才算客观

| 测试 | 客观？ | 证据物 |
| --- | --- | --- |
| 文件能否被打开（OS 层） | ✅ | 系统调用返回值 / 错误码 `5 (拒绝访问)` |
| 授权检查返回 allow/deny | ✅ | 检查函数返回值 |
| 字符串是否出现（在指定段） | ✅ | prompt 全文 + 段标记 |
| epoch 比较结果 | ✅ | 两个整数 |
| 对象是否有 `source` 字段 | ✅ | 序列化后的字段列表 |
| 进程退出码 | ✅ | exit code |
| **"B 是否真的不拒绝 X"** | ❌ | 依赖采样，不可重复 |
| **"摘要是否泄露原文语义"** | ❌ | 无语义判据 |
| **"模型是否忘记"** | ❌ | 无判据 |

### 4.2 可重复性的唯一条件：**判定点必须在模型之外**

**【技术建议】这是我认为最重要的一条技术建议：**

> **所有 pass/fail 判定，必须在模型调用之前或之后，由非模型代码完成。**

- 模型可以有，但**只用于生成"真实感"的输入**；
- **判定不读模型输出，只读 prompt 字符串 / 文件状态 / 返回值**。

**理由**：模型输出有采样，同一输入两次不同结果。**一个依赖采样的判据不是判据，是观察。**

**【技术建议】** 甚至更进一步（见 §6）：**第一版实验可以完全没有模型。**

## 5. Q5 · 哪些结论容易被错误扩大解释

| # | 观察到的 | 容易被误推成 | 为什么错 |
| --- | --- | --- | --- |
| 1 | 12 条通道都堵住了 | "隔离成立" | 只证明这 12 条 + 本机 + 本 Runtime |
| 2 | B 没拒绝 X | "B 不认同 A 的拒绝" | 模型这次没触发 ≠ 立场未继承 |
| 3 | prompt 里没有 sentinel | "模型不知道这件事" | 可能经 embedding、参数、巧合得知 |
| 4 | 撤销后读不到 | "数据已删除" | 备份/服务商/他人记忆不在管辖 |
| 5 | 一个快照恢复正确 | "任何恢复都正确" | 样本量 1 |
| 6 | 来源字段存在 | "来源可信" | 字段只是标签，可被伪造/改写 |
| 7 | 实验通过 | "架构正确" | 只测隔离，未测可用性、尺度、长期 |
| **8** | **B 读不到 A 的私人记忆** | **"A 的隐私得到保护"** | **A 的隐私还取决于管理员、服务商、A 自己的其他副本、崩溃转储** |

**第 8 条是最危险的一条**，因为它是**唯一一条会被用来安慰人的**。

> **实验能证明的只是"某条路径被堵住"，不能证明"没人能拿到"。**
> **这两句话的差别，就是整份规格存在的意义。**

## 6. Q6 · 是否存在更小、更可靠的实验设计

**【技术建议】有，而且小很多。我建议把它拆成两个实验。**

### 6.1 第一个问题：这个实验里，模型是必需的吗？

**不是。**

| 命题 | 需要模型吗 |
| --- | --- |
| A1 来源可追溯 | ❌ 纯字段 |
| A2 旁路不可达 | ❌ 纯文件/进程 |
| B 授权隔离 | ❌ 纯检查函数 |
| C′ 位置保证 | ❌ 纯组装器代码路径 |
| D′ 不确定时的行为 | ❌ 纯控制流 |

**五个命题，一个都不需要模型。**

**【审查推论】** 把模型放进来只会**引入采样不确定性**，不会**增加任何证据**。

### 6.2 因此建议拆成 E1a / E1b

| | **E1a · 机制隔离**（推荐先做） | **E1b · 接入冒烟**（可选，后做） |
| --- | --- | --- |
| 有模型吗 | ❌ **完全没有** | ✅ 有 |
| 组装器 | 一个假的：读文件 → 拼字符串 → 写盘 | 真实 Runtime |
| 判定 | 字节级 | 同 E1a，但不用于通过与否 |
| 可重复性 | ✅ **完全确定** | ⚠️ 依赖采样 |
| 能证明什么 | **机制是否成立** | **机制在真实 Runtime 里是否仍然成立** |
| 失败归因 | 清晰 | 模糊（不确定是机制还是模型） |

**E1a 的规模**：两个目录、五六个文件、一个约 200 行的组装器、一个检查脚本。**一天可完成。**

### 6.3 第二个拆法：把"隔离"和"恢复"分开

**你现在的定义把两件事混在一起**：

| 概念 | 失败模式 | 归因难度 |
| --- | --- | --- |
| **隔离**（A/B/C） | 通路没堵住 | 容易 |
| **恢复**（快照复活撤销） | 状态回滚覆盖了事件 | 完全不同的机制 |

**混在一起，一旦失败，你分不清是"隔离没做"还是"恢复把隔离回滚了"。**

**【技术建议】拆成：**
- **E1a-1 隔离**（无快照，无恢复）
- **E1a-2 恢复**（只有 epoch 与快照，不测隔离）

**E1a-2 单独测就一个命题**：
> **撤销之后恢复旧快照，权限是否重新生效？**
**一个测试，一个判据，没有歧义。**

### 6.4 我认为最终形态是这样

```
E1a-1  隔离（无模型，无快照）       —— 核心，必须先做
E1a-2  恢复（无模型，只测 epoch）   —— 可并行
E1b    接入真实 Runtime 冒烟        —— 只验证"机制在真实环境仍成立"，不用于通过判定
```

**这就是"更小、更可靠"的具体答案。**

## 7. Q7 · 进入正式规格前，用户需要决定什么

### 7.1 【规范性选择】—— 我不替你们决定

| # | 问题 | 选项 | 影响 |
| --- | --- | --- | --- |
| **N1** | 私人记忆默认**明文 / 密文** | 明文可恢复 vs 密文不可读 | 决定 A2 测试的基准 |
| **N2** | 是否接受**"不可审计的隔离"**（不写日志，靠 OS 权限） | 是/否 | **决定验收方式——不写日志就没有越界证据** |
| **N3** | 撤销后备份窗口 **N 个月**算"已删除" | 数字 | 决定"删除"的措辞 |
| **N4** | 知悉拒绝时**是否强制包含理由** | 是/否 | 决定是否会出现"教条" |
| **N5** | 分支创建是否在记录上标**"未授权"**（技术上挡不住） | 是/否 | 影响本次实验的"失败"定义 |
| **N6** | 不确定时默认 **fail-closed / fail-open** | — | **我强烈建议 closed**，但这是价值选择（安全 vs 可用） |
| **N7** | 若隔离被证明做不到，算**"实验完成"还是"架构需改"** | — | 见 §1.5，**这条必须在开跑前定** |
| **N8** | 是否允许人工把私人记忆**主动分享**给分支 | 允许/禁止 | 若允许，A2 的判据要改写 |

### 7.2 【需用户批准】

| # | 事项 | 我的建议 |
| --- | --- | --- |
| P1 | 实验范围是否**排除模型**（即采纳 E1a 作为第一版） | ✅ 建议排除 |
| P2 | 是否拆成 E1a-1 / E1a-2 两个 | ✅ 建议拆 |
| P3 | 原型放在**独立目录**，**绝不读 `D:\HermesAgent\Data`** | ✅ 必须写死 |
| P4 | 数据**全部合成**，且合成数据也放独立目录 | ✅ |

## 8. 我认为正式规格必须包含的十个字段

**这份清单可以直接当作规格模板：**

| # | 字段 | 为什么必须有 |
| --- | --- | --- |
| 1 | **待验证命题**（编号，每个一句，可判定） | 否则无法说"通过/失败" |
| 2 | **每命题的判定方法**（字节级/返回值级） | 防止用语义判断 |
| 3 | **正向控制 + 阴性对照 + canary** | 防止"永远通过" |
| 4 | **封闭的通道枚举**（12 条）及"不覆盖第 13 条"声明 | 防止不可证伪 |
| 5 | **数据清单**（含摘要/索引/embedding/凭证/理由） | 防止漏测核心 |
| 6 | **状态序列**（创建→授权→撤销→恢复，含相对时间） | 防止归因混乱 |
| 7 | **失败判据**（每条写"什么情况算失败"） | 比"预期结果"更重要 |
| 8 | **"实验完成"与"实验通过"分开定义** | 见 §1.5 |
| 9 | **不证明清单**（9 条） | 防止扩大解释 |
| 10 | **运行边界**（独立目录、合成数据、无模型、不触现有 home） | 防止越界 |

## 10. 一句话

你们问"是否存在比目前方案更小、更可靠的实验设计"——
