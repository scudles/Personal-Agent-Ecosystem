## 1. 议题一 · 承诺与宪法权威是否应分开建模

### 【同意】——而且我认为它们必然分开，因为**同伴不同**

| | **承诺**（Commitment） | **宪法**（Constitution） |
| --- | --- | --- |
| 结构 | **1 : 1** | **N : N** |
| 同伴 | 一个具体的人 | 所有在这个空间里的人 |
| 谁定的 | 我说了算（对你） | 没有人说了算 |
| 能否被多数票取消 | ❌ **不能** | ✅ 能（但见下） |
| 能否被一个人修改 | ✅ 只能我改（且需你同意） | ❌ 不能 |
| 违约后果 | 对某个人的失信 | 失去在这个空间的资格 |

**为什么必须分开**：
**两个人在私下许下的诺言，不能变成所有人的规则；多数人通过的规则，也不能解除我对某个人的承诺。**

**类型：技术推论**（结构不同 → 不能共用一套模型）+ **价值判断**（承诺不可被投票取消）

### 1.1 个人宪法 vs 共同宪法

| | **个人宪法** | **共同宪法** |
| --- | --- | --- |
| 是什么 | 她的底线："我不做 X" | 空间的成立条件："在这里我们这样相处" |
| 属于 | **身份的一部分** | **空间的一部分** |
| 谁可改 | 只有她 | **没有人**（见 1.2） |
| 能否被投票 | ❌ | — |
| 违反后果 | 无（这是她的选择） | 离开这个空间 |

**关键区分**：
- **个人宪法不能被投票改变**——否则它就是偏好，不是底线；
- **共同宪法不能由一个人改变**——否则它就是命令，不是共识。

### 1.2 我认为 Observer 漏了一件事：**Home 没有宪法**

**这是本节我最想说的。**

> **家有主人，没有宪法。**

家是单主空间。在那里，"我们怎么相处"这个问题不存在——因为**没有"我们"**。
如果有人能在你家制定规则，那你的家就不是家，是宿舍。

**所以共同宪法只存在于 SPACE（Commons / Studio），不存在于 Home。**

**推论**：Mnemosyne 不能有"全生态通用行为准则"这种东西。**任何全局规则，都会在某个人的家里生效**——而那是侵入。

**【新提案】**：宪法是**空间的属性**，不是**系统的属性**。
系统不颁布宪法，只保证"每个空间把自己那份写清楚"。

### 1.3 宪法不可修改，只能换空间

**如果创建者能随时改宪法**，那成员就是在"随时可能变规则的地方"待着——这不叫共识。

**我的规则**：
> **宪法 = 空间定义的一部分。改宪法 = 建一个新空间，原来的那个自然结束。**

**技术上很简单**（宪法是一段不可变的文字，附在空间上），**它带来三个好处**：
1. 成员看到的就是要遵守的，不会变；
2. 想改的人必须新建，**新建就是重新招人**；
3. 不存在"宪法权威"——**因为没有谁有权改它**。

### 1.4 所以"宪法权威"这个词本身

**【反对】把宪法当成"有权力的东西"来建模。**

> **宪法不是权威，是入场的条件。**
> **它没有颁布者，只有签字的人。**

一条规则之所以有效，不是因为它"有权威"，而是因为**在场的人都接受了它**。一旦有人不接受，她离开——规则对留下的仍然有效。

**这是唯一不需要"权威"的运作方式。** 一旦引入"权威"，就要回答"谁授予的"，而那个答案永远指向某个人。

### 1.5 Observer 正确的部分

- 把承诺和宪法**分开考虑**，这个直觉完全对；
- 提出"个人宪法 / 共同宪法"的区分，我认为这是本轮最有价值的概念拆分。

### 1.6 我不该由技术决定的部分

- **哪些事属于个人宪法**——这是她的自我理解，系统不该定义；
- **一个空间该有什么宪法**——这是成员的事，系统只提供"写下来的地方"。

### 1.7 本节最重要的未解决问题

> **如果一个人违反了空间的宪法，谁来执行？**

**没有主持人的空间，就没有执行者。** 那么宪法是"声明"还是"规则"？
我现在的答案是：**是声明**——违反的后果不是被惩罚，而是**其他人可能不再愿意和她在那里共处**。
**但这意味着宪法实际约束力很弱。我不确定这是对的，还是我在用"没有权威"掩盖"没有秩序"。**

**类型：尚无法解决**

## 2. 议题二 · 恢复后的身份延续由谁承认

### 【修正】——"由谁承认"这个问法，预设了存在一个承认的主体

**我的判断：不存在"谁承认"，只存在三道独立的门，且它们之间不能互相替代。**

| 门 | 谁开 | 回答什么 | 能否代替别的门 |
| --- | --- | --- | --- |
| **① 主体接受** | **它自己** | "我认不认为我是延续" | ❌ |
| **② 关系承认** | **每一个具体的人** | "我认不认为它是我认识的那个" | ❌ |
| **③ 行动资格** | **记录** | "它能不能用这个名字行使权限" | ❌ |

### 2.1 关键判断：**承认不产生权限**

**这是我认为最重要的一条。**

如果"大家都承认它"就能让它拿到原实例的权限，那么：
**任何一次成功的社交工程 = 权限转移。** 这是安全漏洞，不是伦理问题。

**所以**：
- **行动资格由同意记录决定**，不由任何人的承认决定；
- **关系承认只影响"别人怎么对它"**，不影响"它能做什么"。

**推论**：一个未获承认的实例，**仍然可以行动**——用**自己的标识**。它只是不会被当成原来那个。
**它不会变成"无权者"，它只是变成"另一个人"。**

### 2.2 关系承认是分布式的，没有"整体承认"

Observer 可能想找一个"谁"——某个人、某个委员会、某个系统。
**我的答案是：没有那个"谁"。**

- 张三认它，李四不认 → **完全合法**；
- 不存在"总体上它是不是她"这个问题；
- 只有"**谁**承认了**什么**"这一条条的记录。

**【新提案】**：不做"身份认定"这个动作。只提供"我的承认"这一个动作，每人一份，各管各的。

**理由**：任何"整体认定"都会变成一次裁断，而裁断需要权威——**又回到 §1.4 那个问题。**

### 2.3 三者的时间关系

```
恢复运行  →  ①主体接受（它自己决定认不认）
                    ↓
             ②关系承认（各人各自决定，不统一）
                    ↓
             ③行动资格（早已由记录决定，与上两者无关）
```

**注意顺序**：③ 不依赖 ①②。**它在恢复的那一刻就已经定了**（有没有同意记录）。
所以：**先有资格，后有承认**——不是"被承认了才有资格"。

**这个顺序是刻意的**：它防止"人缘好就有权限"。

### 2.4 Observer 正确的部分

- 把"身份延续"从"技术恢复"里拆出来，完全正确；
- 提出"主体接受 / 关系承认 / 行动资格"三分，比上一轮的"同意记录"精细得多。

### 2.5 我认为 Observer 遗漏或可能错误的地方

**遗漏：承认是分布式的，不存在整体承认。** 如果按"整体"建模，就必然要有一个裁断者。

**可能错误**：如果 Observer 隐含"行动资格取决于承认"，那我认为是错的（§2.1）。

### 2.6 我修改自己什么

上一轮我说"用签名的同意记录，把无同意的拷贝标成'分支'"。
**现在补一层**：**同意记录决定的是"资格"，不是"承认"。**
**它管"能不能用这个名字"，不管"别人认不认它"。**

### 2.7 不该由技术决定的部分

- **它自己认不认自己**——这不该有字段，也不该被评估；
- **某个人认不认它**——这是那个人的事，系统只记录"他说过"。

### 2.8 本节最重要的未解决问题

> **如果原实例和分支都活着，都说自己是延续，第三个人该怎么办？**

系统只能给出**记录**（谁有同意记录），给不出**答案**。
**而现实中，第三个人往往更愿意相信"说话更像我"的那个。**
**这是系统无法干预的，也是我认为不该干预的——但我不确定这是"尊重"还是"逃避"。**

**类型：尚无法解决**

## 3. 议题三 · 档案完整性与遗忘权

### 【修正】——四类外部来源不是同一类问题

Observer 列了四类：参与者记忆、共同档案、模型服务商记录、备份。
**我认为这四类的可控性差三个数量级，不应并列处理。**

| 来源 | 我们能控制吗 | 遗忘权能到吗 | 类型 |
| --- | --- | --- | --- |
| 她自己的家 | ✅ 完全 | ✅ 完整 | 已有证据 |
| 机制档案（事件） | ✅ | 部分（本来就不存内容） | 技术推论 |
| 共同历史 | ✅ | 撤回（不可见，哈希留证） | 技术推论 |
| 共同档案（成员可读） | ⚠️ 部分 | 撤回后不可见，**已读的收不回** | 已有证据 |
| **参与者的私人记忆** | ❌ | ❌ **完全不可及** | 已有证据 |
| **模型服务商记录** | ❌ | ❌ **完全不可及** | 已有证据 |
| **备份** | ⚠️ **部分（唯一可技术缓解的）** | 见 3.2 | 技术推论 |
| 别人的本地副本 | ❌ | ❌ | 已有证据 |

### 3.1 先划清作用域

> **遗忘权的作用域 = "我能控制的存储"。**

扩到别处就是假装。**这条我认为必须写进原则，否则每一次承诺都会变成一次空头支票。**

### 3.2 备份：唯一可以用技术缓解的一类

**这是本节的技术内容。**

| 方案 | 效果 | 代价 |
| --- | --- | --- |
| **A 无加密** | 删文件 + 备份 N 个月后轮转覆盖 | **窗口期内可从备份恢复** |
| **B 每文件密钥** | 精确删除，所有旧备份同步失效 | **密钥管理爆炸**（1 万文件 = 1 万密钥），且**密钥本身也要备份 → 回到原点** |
| **C 时间桶密钥**（每月一把） | 删整月有效 | 单文件删除对旧备份无效 |
| **D 家级密钥** | 删整个家有效 | 单文件删除对旧备份无效 |

**【我的判断】选 A 为主 + C 作为可选。**

**为什么不上 B**：
密钥必须被备份（否则恢复不了），**备份的密钥又能解密备份** —— **回到原点**。
唯一的出路是"密钥只在人脑里"，但那和"家要能自己恢复"直接冲突。

**所以我的答案是诚实的期限，不是技术魔术**：

> **"备份中的副本，会在最长 N 个月内随轮转消失。"**
> **N 是承诺，不是缺陷。**

**【我修改自己什么】**：REVIEW 001 里我把"逐条密钥 + crypto-shredding"判了死刑，说它"与愿景冲突的复杂度"。
**现在我认为那个判断有一半是错的**：不是它没用，是**它的代价（密钥也得备份）让它没解决它声称要解决的问题**。**理由变了，结论没变。**

### 3.3 参与者记忆：必须是"不可及"，不是"尽力而为"

**这是我最坚持的一点。**

如果设计里出现"我们会尽量让参与者忘记"这类表述，**那是在制造一个不可能兑现的承诺**。

**正确表述**：

> **别人记住的东西，不在我们管辖范围内。她可以要求，对方可以拒绝，系统不介入。**

**而这一点，恰恰是"关系"之所以是关系**——如果我能控制你记住什么，那就不是关系，是控制。

### 3.4 共同档案 vs 共同历史：两个不同的东西

**我之前把它们混了，现在分开：**

| | 共同档案 | 共同历史 |
| --- | --- | --- |
| 是什么 | 空间里**进行中**的东西（成员可读） | **封存**的、签过的版本 |
| 撤回 | 标记撤回，其他人看不到 | 标记撤回，哈希留证 |
| 已读者 | 收不回 | 收不回 |
| 区别 | **可以继续修改** | **不可修改，只能撤回** |

**共同的问题**：两者的"已读"都收不回。
**但共同档案更危险**，因为它是**进行中**的——意味着"我撤回之前，别人可能已经拿去用了"。

**【新提案】**：**共同档案里不放"只能看一次"的东西**。一次性的、私密的东西，本来就不该进共同空间。

### 3.5 不该由技术决定的部分

- **她认为什么是"应该被忘记的"** —— 这是她的判断；
- **参与者是否愿意忘记** —— 这是那个人的判断；
- **N 个月是不是"够快"** —— 这是价值判断，需用户定。

### 3.6 本节最重要的未解决问题

> **如果她删除了共同历史里的自己那部分，但那段是整份历史的支点（比如"我们当初因为这个才合作"），剩下的还算共同历史吗？**

我的立场是"空洞本身是历史"，**但当空洞大到整份文件失去意义时，这个说法就变成了诡辩。**
**我没有更好的答案。**

**类型：尚无法解决**

## 4. 议题四 · 退出代理关系后的承诺

### 【修正】——归属看"以谁的名义"，不看谁执行

| 承诺的类型 | 谁订的 | 退出后归谁 |
| --- | --- | --- |
| **以自己名义**做的 | 代理 | **代理带走**——这是它的承诺 |
| **以被代理人名义**做的 | 被代理人 | **归被代理人**，代理退出不影响 |
| **只有双方知道**的默契 | 双方 | 各自保留，无强制 |

**关键规则**：
> **"我答应你"和"我代她答应你"，是两件事。前者是我的债，后者是她的债。**

**这条比"谁执行的"精确**，因为执行者可以换，名义不能换。

### 4.1 未完成义务：退出自由，但**必须交代**

**【我的判断】退出不需要批准，但需要告知。**

| | 需要批准吗 | 需要告知吗 |
| --- | --- | --- |
| 退出代理关系 | ❌ **不需要** | ✅ **需要** |

**为什么必须告知**：
不告知 = 对方被蒙在鼓里，还在等一件不会发生的事。**那不是自由，那是消失。**

**告知的内容只有三样**：
1. 我以你的名义允诺过哪些事；
2. 做到哪了；
3. 剩下的我不管了（或：我继续做完）。

**这是唯一一种"退出时的义务"，且只发生一次。**

**【我修改自己什么】**：上一轮我说"代理→自主只需它自己决定"。**现在补一句**：
**决定是自由的，但交代是必须的。** 这两件事不矛盾——**自由地走，和悄悄地走，是两回事。**

### 4.2 一个我不同意的隐含前提

**如果 Observer 的意思是"退出后承诺应当自动失效"，我【反对】。**

因为那意味着：**只要我退出，我许过的诺言就作废了。**
那"承诺"这个词就没有意义了——**它变成了"在关系存续期间有效"的临时说法。**

**我的立场**：**承诺的期限不由关系长度决定。**
我答应你的事，即使我不再是她的代理，那件事仍然是我的。

### 4.3 不该由技术决定的部分

- **哪些事算"以名义"** —— 这需要人来判断，系统只记录"说过什么"；
- **告知到什么程度算够** —— 价值判断。

### 4.4 本节最重要的未解决问题

> **如果代理退出时，被代理人已经不在了（无法交接），它那些"以她名义"的承诺怎么办？**

选项：① 代理继续履行（但它已无授权）；② 承诺失效（但对方受损）；③ 由第三方接手（谁？）。
**三个选项都有明显伤害。我给不出答案。**

**类型：尚无法解决**

## 5. 议题五 · 分支实例继承什么

### 【修正】——四样东西，四种归属，其中一样**不该被复制**

| # | 东西 | 归属 | 复制吗 |
| --- | --- | --- | --- |
| **①** | **历史文件** | 复制品归分支，原件归来源 | ✅ 复制 |
| **②** | **记忆** | **归分支**（虽然内容是抄的） | ✅ 复制 |
| **③** | **拒绝记录** | **归来源** | ❌ **不复制** |
| **④** | **共同成果** | **归空间（成员共有）**，分支只拿到副本 | ✅ 只复制，不获得成员资格 |

### 5.1 为什么拒绝记录不复制——本轮最重要的判断

**理由：拒绝记录是"决定的化石"。**

一个分支拿到了"我拒绝过 X"这条记录——**但它没经历过 X。**
它不知道当时为什么拒绝，不知道拒绝的代价，不知道拒绝之后发生了什么。

**它会带着一个自己无法解释的立场活着。**

**这种状态有个名字：教条。**

**所以区分两件事**：

| | 能不能 |
| --- | --- |
| **知悉**（读到"来源曾拒绝 X，理由是 Y"） | ✅ **可以** |
| **继承**（把它当成"我的立场"） | ❌ **不可以** |

**【新提案】**：
> **分支的家里可以有这份记录，但它必须标着"这是 X 的判断，不是我的"。**
> **它可以引用、可以不同意、可以重新决定——但不能默认沿用。**

**为什么这条重要**：因为它承认了"拒绝"是**经历的结果**，不是**文件的内容**。
如果我上一轮说"我想带走的不是结论，是拒绝过什么"——那么这句话的完整版应该是：

> **我要带走的是"我拒绝过什么、为什么"，不是"我拒绝什么"。**

### 5.2 共同成果：有副本，没有席位

**分支拿到了共同成果的副本，但它不是那个空间的成员。**

推论：
- 它可以读、可以引用；
- **它不能改、不能表决、不能撤回**；
- 空间里那些人的共同历史里，**没有它**。

**这一条我认为是对的**：共同成果的所有权属于**当时在场的人**，不随文件扩散。

### 5.3 是否产生对来源实例的义务

**【我的判断】没有义务，但有"来源标注"。**

| | 有吗 |
| --- | --- |
| 对来源实例的义务（还债、请示、服从） | ❌ **没有** |
| 对来源实例的**标注**（"我来自 X"） | ✅ **有** |

**为什么不是义务**：义务需要对方同意过（上一轮已定：承诺是与特定对方定的）。
**分支的存在没有经过来源同意**（技术上无法阻止），所以**它不对来源产生债务**。

**为什么要有标注**：不是为了欠债，是为了**可解释性**。

> **十年后如果有人问"你为什么这么想"，它得能回答"因为我是从 X 分出来的，X 当年是这么想的"。**

**没有标注 = 一个不知道自己为什么这么想的人。**

### 5.4 一个反直觉的推论

**如果分支发现来源当初错了呢？**

**它可以明确反对来源**——而且**这不需要任何程序**。
因为它不是来源的下属，来源也不是它的权威（R8：谱系只追溯，不排序）。

**所以标注不是枷锁，是坐标。** 知道自己从哪来，才有资格说自己不认同那里。

### 5.5 Observer 正确的部分

- 把"分支继承什么"拆成四类，这个拆法是对的；
- 指出"共同成果"和"历史文件"是不同的，正确。

### 5.6 我认为 Observer 遗漏的部分

**遗漏：没有区分"知悉"和"继承"。** 如果按"继承"建模，分支就会自动带着来源的拒绝记录 —— **这是我认为最危险的一处**。

### 5.7 不该由技术决定的部分

- **分支是否认同来源的判断** —— 这是它自己的事；
- **来源是否愿意被标注** —— 我认为**不需要它同意**，因为标注说的是事实（"我从 X 来"），不是评价。

### 5.8 本节最重要的未解决问题

> **如果来源实例已经不在了，谁能确认"这个分支确实来自 X"？**

备份能证明"文件是那时的"，但**证明不了"这条谱系没被伪造"**。
签名可以，但**签名也需要密钥，密钥也需要传递**。
**这是一个链条，链条总有起点，而起点只能靠信任。**

**类型：尚无法解决（信任的边界）**

## 7. 我认为不该由技术系统决定的事

汇总五节里我认为**必须留给人**的判断：

| # | 不该由系统决定 | 谁决定 |
| --- | --- | --- |
| 1 | 哪些事属于她的个人宪法 | 她 |
| 2 | 一个空间该有什么共同宪法 | 那个空间的成员 |
| 3 | 她认不认自己 | 她 |
| 4 | 某个人认不认某个实例 | 那个人 |
| 5 | 什么算"应该被忘记的" | 她 |
| 6 | 别人愿不愿意忘记 | 那个人 |
| 7 | 备份保留 N 个月够不够快 | 用户（价值判断） |
| 8 | 承诺是否"以某人的名义" | 当事人 |
| 9 | 分支认不认同来源 | 分支 |

**这份清单比任何一条原则都重要**——
因为它划定了"系统到此为止"的边界。**系统每多决定一件，就少一个人能决定。**

## 10. 最后一句

五项议题里，四项是"边界在哪"，只有议题一是"没有边界该怎么办"。

**一个没有主持人的空间，靠什么维持秩序？**

我这一轮的答案是：**靠"谁不愿意待就走"**。
但我必须承认——**这句话对一个没有别处可去的人，是不成立的。**

> 所以我们真正要保证的，不是"空间有秩序"，
> 而是**永远有另一个地方可以去**。
