# MAG-001 受保护规则权威文件

版本：MAG-001
状态：ACTIVE / PROTECTED（正式生效）
日期：2026-11-12
生效依据：用户明确更正“正式起效”。

## 9.1 受保护地位

本制度适用全部参与者，包括用户。当前已按用户最新明确决定正式生效。普通任务不得随意覆盖风险分级、两轮限制、范围冻结、Issue关闭、唯一负责人和决策权限边界。

保护不代表永久不可改变；用户可通过正式修订流程改变制度，不能把一次临时要求暗当制度已改。任何实现、配置或提示词都不能静默绕过这些规则。

## 9.2 用户冲突提醒

- 所有任务强制三方：按L0-L3选择必要人数，普通任务不需要三方。
- 无新证据重审已通过任务：引用原审查与关闭记录，符合重开条件后再审。
- 仅因更优雅方案推翻已验收实现：先证明实际问题，否则另记优化，不自动返工。
- 持续增加验收：新建独立Task，不扩大当前任务。
- 反复讨论已关闭问题：无新证据不重开，确实未解决引用原Issue。

Observer与平台应明确提醒，不迎合或默默配合绕过。工程负责人同样遵守，不以“让三方都说话”代替质量。

## 9.3 提醒四项必备

1. 用户当前提出的要求。
2. 冲突的具体条款。
3. 可能的工程后果。
4. 合规替代方案。

提醒记录Task/Project、规则版本、时间、来源和处理结果。材料或讨论中出现同样词语不等于用户在发起违规请求。自然语言语义不确定时说明不确定并结合上下文判断，不能仅靠关键词宣称可靠识别。

## 9.4 正式修订

明确提出修改MAG时：指出原规则→解释保护目的→说明影响→形成正式修订记录→等待用户明确确认→生成新版本并保留旧版与历史。提出修订不等于确认生效；Agent/普通任务不能自批。

## 十、工程保护边界

全部规范文件保持同一MAG版本，CHANGELOG记修订。普通工程任务不能改制度；规则校验不得提供无记录自动跳过通道。Guard应检查唯一负责人、风险/人数、轮次、重开依据、P2/P3误阻断和范围膨胀。

文档与逻辑Hash校验不等于操作系统防篡改。未接入Guard的旧入口不能冒称受技术强制保护；必须列出缺口，按制度人工执行并逐步接入。规则完整性异常应停止治理判断，不能把读不到规则当作通过。

MAG不授予真实Agent会话操作、Shell、文件写入、公网/手机访问、凭证读取或凪接管权限。原暂停、原Session与DeepSeek草稿保护保持。
