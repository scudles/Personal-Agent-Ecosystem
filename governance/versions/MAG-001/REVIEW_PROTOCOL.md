# 正式工程审查协议

版本：MAG-001
状态：ACTIVE / PROTECTED（正式生效）
日期：2026-11-12
生效依据：用户明确更正“正式起效”。

## 5.1 输入

Task ID、目标、范围、验收标准、唯一负责人、必要的指定审查者、风险级别、Artifact Package及代码版本/Snapshot。所有审查方基于同一份已核验版本材料。材料未建立或不完整要明确说明，不得当作工程审查证据齐全。

## 5.2 意见严重程度

- P0：严重安全、数据损失、致命错误，必须停止。
- P1：验收不通过或核心错误，必须修复。
- P2：非阻断缺陷或维护改进，可延期记录。
- P3：风格偏好/个人建议，不要求修改。

正常工程交付只有未解决P0/P1可以阻断。P2/P3不得因个人偏好阻止交付。若P2实际有严重安全证据，重新评估严重程度，保留依据，不机械依赖标签。

## 5.3 原则最多两轮

第一轮一次性提交阻断问题、非阻断问题、建议、证据和验收判断，尽量发现当前材料可识别的问题。

第二轮只核对原P0/P1是否解决、修改有效性、回归及相关验收；不重新扩大整个范围。除新证据、实质修改或新重大风险外，不启动第三轮完整审查。例外必须记依据和与旧审查关系，不清空历史计数伪装首轮。

未解决P2/P3可入技术债，无阻断问题且验收通过可交付。

## 5.4 新需求

超出已确认范围的新要求建立独立Task ID，不自动改变原任务或无理由阻断当前交付。

## 与现有正式审批的区别

工程复核的Issue判断不等于用户主动发起的正式审批票据。现有正式审批仍要求其指定审查者明确无条件通过；不把每项工程任务都送入该审批通道，也不把P2/P3建议包装成必修条件来绕过本制度。需要制度层面改变正式审批规则时走正式修订，不静默弱化旧保护。
