# MAG-001 — Phase 0 工程核对

当前未发现governance目录、MAG版本登记、L0-L3风险等级或Issue生命周期实体。现有协作包含唯一Task执行者、显式收件方、预算/轮次上限、严格正式审批、用户授权分离及审计，可以复用但不能冒称已实现MAG。

冲突与处理：

1. 旧正式审批要求全部指定审查者无条件通过；MAG要求普通工程交付仅P0/P1阻断。两者必须区分：工程复核按风险/Issue判断，用户明确发起的正式审批仍按既有审批规则；不能把P2/P3建议塞进正式审批条件再冒称MAG允许其阻断。
2. 旧默认UI可能选择全部审查者；不能作为MAG推荐流程。治理接口按L0=自测、L1=一名、L2=一名且第三方需理由、L3=专项审查并按风险决定人数。
3. 现有审查轮次是材料自动修订限制，不等于MAG两轮审查。Guard单独记录审查轮数和重新开启依据，不重写旧历史或清空计数。
4. UEC仍处于仅审计阶段，尚无真实Artifact Package；没有材料时不能把工程正式审查标为证据完整。文字讨论不冒充工程审查。
5. 三个原生通道暂停/硬锁。制度生效不等于已向其他原Session投递或收到它们确认；本轮不发送。

采用用户最新明确决定：“更正为正式起效”。MAG-001登记为ACTIVE/PROTECTED，保留之前候选选择与此次更正的决策记录。

本轮代码只在governance内提供结构化Guard和模拟验证；不把库函数存在等同于所有旧HTTP入口已经强制接入。未覆盖的自动化边界必须在交付中明确。当前工程任务按正式制度由负责人执行，旧入口的全面拦截需后续分阶段接入，不能宣传已完成。
