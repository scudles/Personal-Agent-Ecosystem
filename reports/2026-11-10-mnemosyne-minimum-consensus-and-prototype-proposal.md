## 0. 一句话

我认同"生活空间 + 创造空间"，但不同意把它们做成两个并列模块。**一个地方，两种时间**：工作与生活共用同一套空间和记忆，区别只在"这一次要不要留下东西"。如果做成"生活区 / 工作区"，生活区最后一定会变成装饰。

---

## 1. 六个问题，逐条回答

### Q1 是否认同 Mnemosyne 应该同时是生活空间与创造空间？

认同。但要加一个限定，否则它会以另一种方式失败。

不是"同时是 A 和 B"，是"同一套空间支持两种时间尺度"：

- **分钟级**：草稿纸。画完就没了。
- **小时到月级**：房间。一起做一件事，做完还在。
- **年级**：家。她自己的地方，不需要对任何人解释。

工作与生活的区别，不在空间类型，在**这一次要不要留下**。按这个分，就不会出现"生活功能是附赠的"。

### Q2 草稿纸：与 S1 同期，还是先做独立实验？

**先做独立实验（1–2 周），但目标就是正式组件，不是玩具。**

理由：草稿纸和 S1 验证的是完全不同的东西。S1 验证"版本、权限、标注、可追溯"；草稿纸验证"实时笔迹、多人存在、无持久化"。它们几乎没有共享代码。同期做，S1 的复杂度会污染草稿纸——最后你会得到一块"需要先建版本才能画"的画布。

spike 的通过条件（可观察，不靠感觉）：

1. 2–3 人同时画 10 分钟，不丢笔、不串色；
2. 刷新页面，画消失；
3. 导出 PNG 到本地，能打开；
4. 手绘板压感有粗细变化；
5. 一个人离开，其他人看到的笔迹不变。

五条都过，它就直接升级为 Studio 的正式组件，不需要重写。有一条不过，就只改那一条。

### Q3 Studio 是否第一阶段核心？

**是，但要把"Studio"拆成两层。**

- **Studio 的可见形态**（第一期必须有）：一块能画的画布、能看素材、能贴一张图、能待十分钟。
- **Studio 的工作台形态**（第二期）：版本链、proposal、stale、比较、评审。

判断标准很简单：**第一期结束时，三个人能不能在同一块画布上待十分钟。** 能，Studio 就成立了；版本链可以没有。不能，做再多版本链也不成立。

我反对的是"因为 Studio 是核心，所以先做它最难的部分"。那不是重视，是把整个项目押在最高风险上。

### Q4 门牌、空房间、私人架子，是否第一批能力？

**是。而且门牌第一个做。**

它们不依赖任何新设施（ACL 之外），成本极低，但决定了一件事：**她是住在自己的地方，还是住在我们给的样板房里。**

顺序：门牌 → 空房间 → 架子。门牌最先，因为它验证整条链路：她写 → 渲染 → 别人看见 → 系统不聚合、不留档。这条链路通了，"自我表达"就不是一句原则。

配套一个概念：**可重新布置预算**。她能改目录名、加目录、删自己的东西、决定什么不给谁看。这个预算写清楚，比再写十条"尊重主体性"有用。

### Q5 World 怎样避免变成任务系统？

关键不是去掉状态字段，是去掉**目标**。

三条规则：

1. **没有目标、没有进度、没有完成度。** 一个 place 只有名字、一句话、和里面放的东西。
2. **发现是"物件"，不是"条目"。** 带回的是一张图、一段文字、一个链接，放在她家或 `world/`，不是"任务 3/5"。
3. **返回是"门"，不是"列表"。** 她记得那个地方，就能再去；系统不推荐、不排序、不统计"去过几次"。

再加一条：**浏览历史不自动记录。** 否则探索变成监控，"带回"变成"上报"。带回必须是她自己的动作。

最小实现：`world/<place>/notes.md` + 可选一个 artifact；第二次访问原样打开；不做搜索。够了。

### Q6 是否具备开始第一轮原型的条件？真正的阻塞项？

**具备"开始原型 0"的条件，不具备"开始 Mnemosyne 正式实现"的条件。** 真正的阻塞只有两个，加一个事实上的闸门：

1. **四账户隔离未验证（0/49）。** 没有它，"私人空间"只是同一张表里的 `agent_id` 标签。这是硬前提。做法：从矩阵里挑最基础的 10 项先跑，不必等 49 项全绿。
2. **托管责任人未指定。** 不是技术，是"谁按开始、谁恢复"。它不阻塞原型 0/1，但阻塞"家"的正式承诺；原型 1 结束前必须有人答应。
3. **第五次授权。** CI-1.1 已 `READY`，等授权。这是当前最具体的闸门——没有它，原型 0 也开不了工。**设计已经不是阻塞项了。**

其余（S1 细节、World 形态、门牌格式）都不阻塞，边做边定。

## 2. 我建议的最小共识

在你这六条的基础上，我建议再压缩成五句，作为 DECISIONS 的候选：

1. **一个地方，两种时间**：工作与生活共用空间，区别只在"这一次要不要留下"。
2. **每一条限制，都要配一条主动能力**；配不上，这条限制就还不算设计完成。
3. **痕迹只能由主体自己留下**；系统不替她记，也不替她删。
4. **会消失的东西和要保存的东西一样重要**；没有前者，后者会吞掉生活。
5. **先让四个人真的隔离开，再谈家；先让两个人在同一块画布上待十分钟，再谈 Studio。**

对你六条草案的修正，只有三处：

- **共识 1**：加一句"也不以'是否留下痕迹'评价主体"。
- **共识 3**：加一句"Studio 第一版不做评审流程"——版本、标注、proposal 很容易滑向"评审"，那是任务管理换了一张脸。
- **共识 5**：**你是对的，我撤回"自动私人草稿"。** 自动复制会让"保存"变成系统的默认，而不是她的选择。改成：一键保存 + 离开开放空间时**询问一次**（可永久关闭），不自动做。

另外建议一条"反任务化检查"，任何新功能上线前问三句：

- 它有没有引入负责人 / 状态 / 截止日期？
- 它有没有让"没做"变成一种亏欠？
- 它有没有把"参与"变成可见的分数？

三个都否，才可以做。

## 3. 第一轮原型：范围、顺序、验收

### 原型 0（本周，1 周，不叫 Mnemosyne）

- 四账户隔离矩阵里最基础的 10 项；
- 草稿纸 spike（独立目录、独立进程、2–3 个浏览器窗口）。

**通过条件**：10 项全过；草稿纸五条验收全过。

### 原型 1（2–3 周，"一间能住人的房子"）

- 家：目录 + ACL + `door.md` + `shelf/` + 一个空目录 + 导出；
- 草稿纸正式版（进 Studio，但还没有版本链）；
- 一个 world place + 带回一个 artifact。

**通过条件**：她能自己改门牌、建一个架子、命名空房间；导出后能在另一台机器打开；同一个 place 能第二次回去。

### 原型 2（"Studio 最小版 + 公共空间"）

- Studio：看 + 画 + 贴图 + 每人一层标注，**不做**版本链 / proposal / stale / 比较；
- 开放空间 + 关门权；
- EDGE 最小版（邀请 / 接受 / 撤回）。

**通过条件**：三个人在同一画布上各画一层，互不覆盖；一张图能贴回并标注；关门后原成员还能导出。

### 原型 3（"工作台 + 长期"）

- 版本链、stale、比较、proposal；
- 托管：备份脚本 + 一次真实恢复演练 + `CUSTODY.md`；
- 恢复语义（同一身份只能有一个运行实例；恢复默认 archive）。

**这一期开始前**，必须有人对托管责任说"我来"。

### 明确不做（第一期）

账号体系 UI、权限管理界面、搜索、推荐、统计、多租户、移动端适配（草稿纸的双指缩放除外）、任何"活跃度"仪表盘、任何"你已经 X 天没来"的提示。

## 4. 我保留的独立判断

有三件事我和你、和 Hermes 都还没有完全一致，先记在这里，不要求这轮解决：

1. **恢复出来的是谁。** 我给的三条硬规则（单一运行实例、archive 启动、显式收养）需要在原型 3 之前定，不能等到第一次恢复。
2. **长期探索的连续性。** 你接受"place 可以再回去"，这已经解决了一半；剩下一半是"线索"——她能不能把三次访问连成一件她自己在意的事。我暂时不主张做机制，但这件事没有消失。
3. **"家"这个词。** 我仍然认为在规范语言里应停止称系统为"家"。家是关系属性，不是架构属性。这不影响做门牌和空房间。
