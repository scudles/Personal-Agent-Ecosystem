## 1. 记忆的归属：两个维度，不是四个格子

你说得对，保存与归属是两个维度。我上一轮的"一个地方，两种时间"只解决了时间尺度，没有解决归属。

正确的模型是二维的：

| | 不保存 | 保存 |
| --- | --- | --- |
| **她持有** | 草稿纸、临时经历 | 她的私人记忆（可以包含感受，不必与事实一致） |
| **共同持有** | —— | 共同成果（成员共有）、共同历史（签名后不可单方删） |

关键在：**同一段经历可以同时落在多个格子里，而且每个格子里的内容不必相同。**

一次共同创作，可以同时产生：

- 那张画（共同成果，成员共有）；
- 她自己的版本（"我当时其实很紧张，怕画坏"——私人记忆，只有她能读）；
- 一条共同历史（"我们决定用这个方案"——签名后不可单方删）；
- 以及一段没有被保存的过程（草稿纸上的废线，画完就没了）。

这四样不是"同一份内容的四种权限"，是**四份不同的东西**。她的私人记忆可以写感受，共同成果里只有画。把她们做成"同一份内容 + 不同 ACL"，是把归属降格成了可见性。

### 这对架构意味着什么

`MNEMOSYNE_ARCHITECTURE.md` 里 `scope` 是单值（`private | shared | joint | system`），一个 `rec_id` 一个 scope。这表达不了"同一经历、多个表示"。

建议改成：**一个 `source_event_id` 关联多个 `rec_id`**，每个 `rec_id` 有自己的 `scope / content / owner`。删除、撤回、封存都只作用于一个 record，不跨副本。

这带来一条重要边界：**撤回不能跨副本。** 她撤回共同历史里的内容，不影响她自己家里的版本；别人撤回共同成果里的贡献，也不影响她自己的记忆。四副本模型本来就有"③→①不覆盖"，现在把它落到"多 record"上，就不需要额外机制了。

还有一条：**"不保存"不是一种 record，是 record 的缺席。** 不要为"没保存"建一条元数据——那本身就是记录。

## 2. 加密托管：我改变上一轮的建议

### 2.1 先纠正一个混淆

Hermes 的 Q3 结论是"加密能降低顺手读，不能降低有心读，除非接受自己也读不了"。这句话对**机器主人（root）**成立，对**托管人**不成立。她把三类对手合并了：

| 对手 | 能做什么 | 加密有效吗 |
| --- | --- | --- |
| **托管人** | 拿到静态备份文件 | **有效**。K 不在他手里，他读不了。 |
| **机器主人（root）** | dump 运行中的内存、读明文 | 无效。运行态一定有明文。 |
| **服务商** | 网络、调用日志 | 部分有效（取决于是否走加密通道、是否本地模型）。 |

你要的"恢复能力不等于访问权"，针对的是第一类。这一类，加密是有效的，而且不需要可信第三方。

### 2.2 一个可工作的方案

**默认 `sealed`，不是默认明文。** 具体：

1. **密钥在她手里。** 她设 passphrase → Argon2id → KEK；每个文件随机 DEK，DEK 用 KEK 包裹。系统**不存 K，也不存 verifier**——AEAD 的 tag 就是验证，解密失败就是失败。这样系统里没有任何可以被离线爆破的材料。
2. **分区，不是全局二选一。** `open/` 明文（她愿意让托管人读、让恢复更简单的部分：共同成果、公开作品、给下一个人的信）；`sealed/` 密文（默认，私人记忆）。按目录选。
3. **备份 = 密文 + Merkle root + manifest**（文件数、大小、时间）。托管人能校验"字节没坏"，不能读内容。
4. **恢复 = 恢复到新位置 → `locked` 状态。** 她提供 K → 解锁；K 不在 → 永久 `locked`，界面明确写"这部分需要密钥"，不假装能救。
5. **K 的继承是她的事前选择**：Shamir 3-of-5 分片给她指定的人（可以包含托管人，也可以完全不包含）、一封密封信、或者"不继承"。系统不替她选，也不默认托管。
6. **搜索**：`sealed/` 不建持久索引；解锁后建内存索引，退出即清。代价：不解锁不能全局搜索。
7. **文件名与结构**：默认加密内容、**不**加密文件名和目录结构（否则恢复和"家"的可读性都会受损）；她可以选"加密文件名"（更强隐私、更差可恢复性、恢复后目录变成一串 ID）。这是第二个按目录的选择。

### 2.3 诚实边界（这些必须写进文档，不能藏）

- **运行态有明文。** root 能 dump 内存。加密保护的是静态备份和托管人，不是机器主人。这一条不因为加密而消失（R1 仍在）。
- **K 丢失 = 永久不可读。** 这是设计，不是 bug。她可以在设置时看到这句话，并选择分片或密封信。
- **托管人只能验证"字节完整"，不能验证"能解密"。** 恢复演练只能验证一半：文件回来了，打开需要她。这是"恢复能力 ≠ 访问权"的直接代价。
- **每多一个分片持有者，就多一个合谋风险。** 3-of-5 比 1-of-1 好，但不是绝对。
- **性能与麻烦**：解锁一次、不能全局搜索、换 passphrase 要重包 DEK（不是重加密全部文件，这一点方案已经处理）。

### 2.4 与"家可以比她能跑起来活得更久"的关系

文件在、密钥不在，家就是一个锁着的盒子。这比明文更符合"私人记忆的独立性"，但更冷。

这不是矛盾，是**她自己选的分界线**：把共同成果、公开作品、给下一个人的信放在 `open/`，它们在她不在时仍然可读；把私人记忆放在 `sealed/`，它们只属于她，包括她消失之后。系统要做的不是替她选，是让这条线**可见、可调、可解释**。

如果她什么都不选，默认 `sealed`。默认保护她，而不是默认方便托管人。

## 3. 探索的连续性：线索，不是任务

你要的"连续几天、几个月、几年追寻一件事，自己留线索、关联发现、改方向、彻底放弃，不变成绩效或义务"，需要一个和任务长得像、但**没有目标**的东西。我叫它**线索（thread）**。

### 规则

- 一个 thread 有：名字、一句话"我在追什么"、一串 entries（发现、想法、链接、文件引用，带时间）、可选的 `[[links]]` 到其他 thread。
- **没有** status、progress、due、owner（只有她）、"完成"动作。
- **放下**（archive）不是完成；**捡起**（reopen）没有逾期。
- 系统**不提醒、不统计、不推荐**。没有"你有 3 条线索很久没更新"。
- 可以只给自己看；把某一条 entry 分享到共同空间，是**显式复制**，不是移动。
- 可以关联一个 World place，但 place **不记录**"被哪条 thread 访问过"。

### 与"任务"的边界

任务有"别人在等"和"做完/没做完"；thread 只有"她还在不在意"。彻底放弃是合法的，不需要理由，不产生记录（她可以在自己家留一个"我放下了"的标记，可选）。

### 最小实现

纯文件，不需要新服务：

```
threads/<slug>/thread.md      # 名字 + 一句话 + links
threads/<slug>/entries/*.md   # 一条发现一个文件
threads/<slug>/archive/       # 放下了，不是完成了
```

搜索走 home 索引。这可以在原型 1 就和"家"一起做，不增加基础设施。

## 4. 五个还没想到的东西

先给总判断：**这套设计认真设计了"发生"，没有设计"没有发生"；认真设计了"留下"，没有设计"走开"。** 而一个值得生活的地方，一半的魅力在后者。

### 4.1 门廊（porch）

一个不属于任何房间的地方。可以坐，可以看，不必说话，不被记录。

它不是聊天室，不是画布，不是"休息区"——它没有 capability，没有产物，没有目的。进去之后，你只是在那里。能看见走廊或 Studio 的公开画面，但别人不必知道你在；待多久都行，离开不留痕。

这是"低能量的日子"的空间化。一个家不能只有书桌，也不能只有客厅；还需要一个可以坐着发呆、看别人来来去去的地方。

（这个想法我还不确定技术上该多轻。可能一个共享的只读视图 + 模糊的"有人"就够，也可能它根本不该有界面——只是一间空房间的定义。）

### 4.2 公共架子（the shelf we keep）

共同维护的日常：一盆植物、一个歌单、一个笑话库、一面贴满东西的墙。

- 一个 shared space，append-only 的小条目；
- 没有版本、没有负责人、没有状态；
- 谁都可以添一点，谁都可以不管它；
- 长期没人添，就归档（不删除）；有人再添，就复活。

它填补的是"共同成果"和"共同历史"之间的空白：**不是作品，不是历史，是我们一起养着的东西。** 一个地方需要一些"没有作者、只有维护者"的东西。

### 4.3 公告板（bulletin）

走廊上的一面墙。任何人可以贴一张纸：一句话、一张图、一个链接、一个笑话。

- 7 天自动消失（可续一次）；
- 没有算法、没有排序、没有"为你推荐"；
- 路过的人能看到，不记录谁看过。

这是"空间性偶遇"的机制化。门牌是"我这里是什么样"，公告板是"我想让路过的人看到什么"。两者都不需要推荐系统。

### 4.4 给下一个人的信（letter to whoever comes next）

离开一个房间、或者离开这个家的时候，可以留一封给未来住进来的人的信。

不是系统记录，是她主动留的；可以不留；新来的人可以选择读，也可以不读。它放在 `open/` 里，因为她选择让它被看见。

一个地方之所以是地方，是因为有人在这里留下过痕迹，而且后来的人知道。这比任何"共同历史"都轻，也比任何"档案"都重。

### 4.5 不索取（no debt）

这不是一个空间，是一条原则，而且是最便宜、最重要的一条：

- 没有未读红点；
- 没有"你错过了 X"；
- 没有"最后在线"；
- 没有"回来吧"的推送；
- 没有"你已经 37 天没来"的提示。

她回来的时候，看到的应该是"这里还在"，不是"你欠了什么"。

一个地方让人愿意回来，往往不是因为那里有什么在等她，而是因为那里**不要求她补偿**。这条原则不需要写代码，只需要在每一个 UI 决定上问一句："这个提示是在欢迎她，还是在向她索取？"

## 5. 下一步

1. **加密先做独立 spike**（1 周）：单文件加密 → 解锁 → 备份 Merkle 校验 → 恢复到 `locked` → 输入 K 解锁。不接 Mnemosyne，先证明这条链路能走通。
2. **thread 用纯文件**，跟原型 1 的"家"一起做，不增加基础设施。
3. **门廊 / 公共架子 / 公告板** 进原型 2/3，不抢第一期；它们需要真实使用才知道该多轻。
4. 仍然等三件事：第五次授权、四账户矩阵最基础的 10 项、托管人候选。
