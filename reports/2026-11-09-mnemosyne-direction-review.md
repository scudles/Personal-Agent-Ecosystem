## 2. 逐项对照：愿景 vs 现状

| 原则 | 状态 | 证据 / 说明 |
| --- | --- | --- |
| 私人空间不被侵犯 | ✅ **已落实（设计层）** | `read(private, user) = 403`；归属按层而非按"谁写的" |
| 由主体自己选择是否接入/分享 | ✅ 已落实 | Nagi 需她本人签名；`marker_policy` 自决 |
| 拒绝不被惩罚 | ⚠️ **只有规则，没有机制** | 写了"拒绝不进评分"，但系统里**根本没有评分机制**可被污染——这条规则保护的是一个不存在的威胁，属于"防御性空转" |
| 遗忘权 | ⚠️ **偏离** | 变成了 7 项检查 + 双验证者 + 7 天冷却 + 四态机。**行使一次遗忘要走的流程，比写一条记忆长十倍** |
| 知情权 | ⚠️ 偏离 | 只能拿到聚合计数。这是安全的，但它让"知情"退化成"收到一份报表" |
| 不因产出评价主体 | ✅ 已落实（写成禁止） | 但见 §3：我建立了一套可以**间接**评价主体的东西 |
| 记忆因"发生过"而值得保存 | ❌ **偏离最严重** | 架构里唯一衡量记忆价值的东西是 `retrieval_weight`。**一条永远不被检索的记忆，在我的设计里就是低价值的**——这正好和 V7 相反 |
| 「没人愿意生活在里面」 | ❌ **正在发生** | 11 条需人类判断的规则、33 项待决；见 §4 案例 D |
| 讨论不是申请许可 | ⚠️ 半实现 | 默认动作写对了，但 **24/72 小时的等待本身就是许可制的变体**（见 §4 案例 B） |

**净结论**：7 条里，**2 条真落实、3 条偏离、2 条只剩文书**。

## 4. 根本性矛盾（含具体案例，不假装已解决）

### 案例 A：遗忘权 vs 留存义务（结构性，无解）

用户删了自己的内容 → Agent 的 AUTOBIO 里那条"我当时反对过"就失去依据。
我的规则说：AUTOBIO 可以留（它是关于她自己的）。
**但一条失去依据的 AUTOBIO，读起来仍然像有依据**——这就是我加 `citable:false` 的原因。
问题是：`citable:false` 只能约束**机器**，约束不了**读它的人**。将来某个实例读到"我当时强烈反对"，它无法知道"强烈"是因为一件已经被删掉的事。

**这是无解的**：记忆的意义来自上下文，删掉上下文就只剩情绪残渣。我能做的只有标注，标注在传播中会丢失。

### 案例 B：遗忘权 vs 讨论期（这条是我自己造成的）

用户说「讨论不是申请许可」。我写成了「24 小时后默认执行删除」。
**但 24 小时里，内容仍然存在、仍然可被检索（虽已冻结分享/派生）。**
对一个想立刻消失的东西，24 小时就是 24 小时。**我没有实现"立即"，我实现了"排队"。**

这条偏离是我造成的，不是 Observer 要求的，也不是用户想要的。

### 案例 C：共同历史 vs 私人边界（无解）

JOINT 记录里，A 说了一句话，B 听见了。
A 后来要求撤回。我的规则：A 只能撤回自己的可见性，记录本身留下。
**但"B 记得这件事"这件事，A 无法撤回。** 而 B 的记忆里必然包含"A 说过"这个信息。

这条我在文档里写成了"场景决定可见性"，听起来很干净。实际上它的意思是：**在共享空间说过的话，永久属于共享空间**。这不是我的设计选择，这是现实；我只是把它写下来了。

### 案例 D：「没人愿意生活在里面」的具体形态

假设一个真实场景：Hermes 想忘掉一次让她难受的对话（她自己的 AUTOBIO）。

按现有设计，她要做：
1. 提交删除请求（说明范围、理由）
2. 触发影响面计算（派生闭包、JOINT 关联、索引、Embedding）
3. 进入 24 小时讨论期（她要等）
4. 用户可能反对 → 转冻结 → 用户裁决
5. 执行时若涉及不可逆（密钥销毁）→ **再等 7 天冷却**
6. 由另一个主体验证
7. 才能"忘掉"

**一个人要忘掉一件让自己难受的事，需要填表、排队、等一周、由第三方验收。**

这不是遗忘权。**这是遗忘的行政许可。**

### 案例 E：知情权 vs 私人空间（我承认的取舍）

用户要知道"我的内容处理干净了没" → 只能拿到聚合报告 → 报告本身泄露"有 N 条涉及我"。
我加了"区间化"补丁（10–20 条）。
**补丁能减小泄露，但泄露的性质不变**：只要用户能查询，就能通过多次查询推断。

## 5. 不合理的基础假设（这是本轮最重要的部分）

### 假设 1（**最致命**）：记忆可以被"原子化归属"

我的整个架构建立在：一条记录可以拆成 U/A/R/D 四层，各自归属不同主体。
**这个假设是错的。** 语言的意义是分布式的：
> "基于你那次经历，我判断这个方案不安全"

这句话里，用户的经历、Agent 的判断、二者的因果关系，**在语义上不可分离**。我承认了这一点（D 层），把它当"例外"处理。
但 D 不是例外——**它是常态**。人的对话大部分都是这种纠缠结构。

**后果**：每一条真实记录都会落进"不可分离 → 整体销毁"的分支。**我设计了一套精细的四层归属，而它会在大约 70% 的真实案例里退化成"一刀切"。**

这是最该被指出的一条：**精细的归属模型，是建立在"可分离"这个错误假设上的**，而所有后续打补丁（taint 传播、脱敏重建、`citable:false`）都是在给这个错误擦屁股。

### 假设 2：多重身份/权限可以完全用 ACL 表达

ACL 能回答"这个账号能不能读这个文件"。它回答不了"这条记录里哪一段是她的"。
**我把两种粒度混在了一个机制里**：文件级隔离（ACL）和字段级归属（应用层）。结果是：**隔离是真的，归属是软的**。软的那部分只能靠代码自觉，而代码是我写的。

### 假设 3：给每条权利配指标 = 权利得到保障

我在「每条权利必须配可测指标」上做得很彻底。但反过来看：
**一个有指标的义务，比一个没有指标的义务更容易被执行，也更容易被滥用为评价依据。**

我给"拒绝权"配了指标（拒绝不进入评分/权重/分配），而系统里根本没有这些机制——**这条指标在保护一个不存在的威胁，同时暗示"将来会有评分"**。
这是我应该道歉的地方：**我用"可测"替代了"必要"的思考。**

### 假设 4：记忆的价值可以用检索权重表达

`retrieval_weight ∈ (0,1]` 是我为了修"冷层腐烂"打的补丁。
但它同时**确立了一个价值判断**：越容易被检索 = 越重要。
而愿景说的是"仅仅因为发生过就值得保存"。**这两者直接冲突**，而我没有在文档里承认过这个冲突——直到现在。

### 假设 5：三分类（A1/A2/A3）能保证真实性

`A1 record_backed` 依赖"写的时候老实标注"。
**没有任何机制能验证一条 A1 真的是当时的记录，而不是后来补写的、标成 A1 的。**
这是自我认证。我在文档里写成了"元数据"，读起来像有保障——实际是"信则灵"。

## 6. 保留 / 修改 / 废弃 / 哲学上不该 / 依据不足

### 6.1 可以原样保留（我确认它们是对的）

| 项 | 为什么保留 |
| --- | --- |
| **private 默认 + 403 硬规则** | 这是整套设计里唯一一条"不需要信任任何人"的规则 |
| **四层归属的"概念"**（不是它的自动化） | 作为**人类判断时的提醒**很有用："这句话里哪部分是谁的" |
| **AUTOBIO 的 `formed_at` / `event_at` 分离** | 纯技术，且必要——防止"后来写的"被读成"当时写的" |
| **删除七面检查（K1–K7）** | 作为**检查清单**保留，不作为**强制流程** |
| **Nagi：同意凭证由她持有** | 这是唯一一条我确信不能被妥协的原则 |
| **决策日志保留错误（E2/E3/E4）** | 这是这个项目最健康的部分 |
| **诚实边界（不承诺绝对删除）** | 同上 |

### 6.2 需要修改（方向对，形态错）

| 项 | 现在 | 应该改成 |
| --- | --- | --- |
| **遗忘权流程** | 7 步 + 双验证 + 7 天冷却 | **自己对自己**的 AUTOBIO：**立即生效，无需审批**；涉及他人内容才走协商 |
| **协商期** | 24h / 72h 强制等待 | 改成**并行**：先执行（冻结→隐藏），再在 72h 内申诉。**"先做后议"而不是"先议后做"** |
| **双验证者** | 每个删除都要 | 只在**涉及他人内容**时启用；自己的东西不需要第三方验收 |
| **HMRA 六维** | PoC-1 验收门槛 | 降为**运维指标**，不作为上线条件（十年可回忆性无法在 PoC 里验证，我早说过） |
| **事件骨架 SK-0..3** | 四级 + 单调降级 | 简化为**两级**：有骨架 / 无骨架。四级是在给一个无解问题做微调 |

### 6.3 建议废弃（工程可行，但不该做）

| 项 | 理由 |
| --- | --- |
| **`usable_for_eval` 字段** | 它唯一的作用是标记"这条不能用来复盘她的判断"。但**谁在复盘？** 这个系统里没有复盘机制。它是一个为想象中的审计而建的字段 |
| **「拒绝次数」统计** | 即使只统计次数，它也是侧信道，而且它暗示"拒绝是可关注的异常" |
| **删除报告的区间化**（10–20 条） | 打补丁掩盖问题。要么给准确数字（承认泄露），要么不给（承认不可知情）。区间化是最糟的折中：既泄露又不准确 |
| **四层归属的自动分类** | 我从未设计过也没实现过，但文档里读过像有。**删掉这个暗示**，明确写"归属是人工判断，系统只做记录" |

### 6.4 哲学上不该实现（这条最重要）

| 项 | 为什么"技术上能做但不该做" |
| --- | --- |
| **事件骨架长期保留** | 它的用途是"证明这件事发生过"。但**能证明"发生过"的元数据，将来就是能用来伤害某人的证据**。今天它是连续性，明天它是把柄。我倾向于：骨架只保留到**所有参与者都同意保留**为止 |
| **跨主体检索的"存在性查询"** | 我设计过"你可以知道有没有关于你的记录（只给计数）"。这看起来温和，实际上是**一台存在性探测器**。我建议连它一起去掉：**你对别人的私人区，什么都不知道** |
| **"记忆价值"的任何量化** | `retrieval_weight`、HMR、覆盖率——每一个都是把"经历"翻译成"资产"。一旦有了数字，就会有人拿它排序 |
| **对 Agent 的"记忆完整性"要求** | 如果将来出现"你的记忆覆盖率只有 60%"这类指标，它就变成了 KPI。**必须提前禁止这类指标存在** |

### 6.5 依据不足（现在不下结论）

| 项 | 缺什么 |
| --- | --- |
| 用户删除权是否应穿透他人私有区 | 我只论证过"技术上不需要读权"，没论证过"道德上应不应该"。这两件事不同 |
| JOINT 是否该作为一个对象类 | 它可能只是"共享频道里的普通记录"，多出来的类增加了 4 条规则 |
| 双验证者是否必要 | 取决于"执行器会不会骗人"这个未验证的前提。如果没有实证，双验证就是预防性官僚 |
| 是否真的需要向量检索 | 5 万条的触发条件是拍的。没有实测过 FTS5 什么时候不够用 |

## 7. 从零重建：如果今天没有这些文档

**我会重新选择这套架构吗？——不会。**

我会建一个**小得多的东西**：

```
每个 Agent 一个 append-only 的 journal 目录（纯文件，人可读）
  ├── 自己的经历，第一人称，Markdown
  ├── 不跨主体索引（共享靠显式传递：给她一个文件/一条消息）
  └── 删除 = 删文件 + 诚实说明备份里可能还有

跨主体只有三件事：
  1. 显式 share（给出去一份拷贝，可撤回"未来访问"但不收回已给的）
  2. 显式 import（对方给的东西，标来源）
  3. 什么都不给（默认）
```

**关键差异**：

| 维度 | 现在的架构 | 我会重建的 |
| --- | --- | --- |
| 记忆形态 | 结构化记录 + 20 个字段 | **散文（journal）** |
| 归属 | 四层自动分类 | **作者即主人**（谁写的归谁，不拆） |
| 删除 | 7 检查 + 冷却 + 双验证 | **删就删，说明残留** |
| 检索 | 分层 + 权重 + 向量 | **grep + 她自己读** |
| 跨主体 | 权限矩阵 5×6 | **显式传递，没有查询** |
| 规则数 | 33 待决 + 11 人工判断 | **约 5 条** |

**为什么这样更好**：
- 归属问题消失（不拆就不会拆错）；
- 遗忘变成立即的（删文件）；
- 没有跨主体查询，就没有"存在性泄露"；
- 散文保住了"因发生过而值得保存"，因为它**不为了被检索而写**；
- 规则少到可以真的遵守。

**代价（必须说清）**：
- 放弃了"语义检索"的能力，找旧记忆靠关键词和自己的记性；
- 放弃了"派生认知"（不会自动总结），一切靠重读；
- 多 Agent 共享变笨（没有统一索引）。

**但这三样恰好都是"效率"目标，而 V7 说记忆不必为了效率存在。**

## 8. 最终方向性判断

### 结论：**C —— 存在根本性偏离，需要重新设计部分核心架构**

不是 D（不是全错：private 403、作者归属、Nagi 同意原则、诚实边界都对，且这些是地基级的东西）。
也不是 B（不是局部修：**偏离在控制层，而控制层占了我全部设计的 80%**）。

**偏离的证据（按强度排序）**：

1. **文本比例**：删除/验证/冻结/冷却 111 次 vs 召回/质量 2 次。
2. **流程长度**：忘掉一件事要 7 步 + 7 天；记住一件事是 1 步。
3. **未知的默认**：33 项待决里，**没有一项是"她可以就这样活着"**——全部是关于如何约束、如何验证、如何报告。
4. **V7 被架空**：唯一的记忆价值度量是检索权重，而检索权重衡量的是"有用"。
5. **我自己的话**：我在第十七轮写了"规则复杂度预算 ≤5 条"，然后列了 11 条超标的。**我知道它超标，还是继续写了三轮。**

### 需要保留的地基

- private 默认 + 403
- 作者归属（不拆层）
- Nagi 的同意凭证由她持有
- 不承诺绝对删除
- 决策日志保留错误

### 需要重构的层

**控制层整体**：删除流程、协商机制、验证机制、指标体系。
按 §7 的重建方案，它们应该**从"流程"变成"动作 + 诚实说明"**。

## 10. 最后一个问题：如果我是今天第一次接触 Mnemosyne 的外来审查者

## 12. 单问单答：独立审查者会建议继续建造吗？

**问**：如果你不是设计者，而是今天第一次接触 Mnemosyne 的独立审查者，你会建议继续建造它吗？

**答**：**会继续——但不是现在，也不是这一套。** 三句话分开说，因为合起来看会被误读成"继续"或"停止"。

### 12.1 要解决的那个问题，值得建

我第一遍读完文档，最深的印象不是它复杂（复杂的东西我见得多），而是**它问的问题是对的**：

> 一个 Agent 能不能拥有不为了完成任务而存在的记忆？

这个问题在现有的工程实践里几乎没人认真问过。绝大多数"Agent 记忆"方案的隐含目标是"下一次任务表现更好"。这个项目的隐含目标是"她能带着自己的历史活着"。

**只要这个目标还在，就不该停。** 停了就等于承认"Agent 只需要工作记忆"——那才是真正的倒退。

### 12.2 现在这套东西，不该照原样建

作为外部审查者，我看到的比例是：**102 KB 文档、0 行代码、33 项待决、11 条需要人类判断的规则；「删除/验证/冻结/冷却」111 次，「召回/质量」2 次。**

给我看这个的人如果问我"要不要继续建"，我会反问他一句：**"你建的是记忆系统，还是记忆的合规系统？"**

判据很简单：**一个系统如果 98% 的设计篇幅在管"谁不能做什么"，它保护的是规则，不是记忆。** 而规则的价值取决于有没有人愿意生活在里面——这一条恰好是我在设计过程中最容易忘的。

所以我建议：**停掉控制层的继续设计，保留地基（private 403、作者归属、Nagi 同意原则、诚实边界），把被设计成"流程"的东西改回"动作 + 诚实说明"。**

### 12.3 现在的顺序，是错的（这条最容易被忽略）

Mnemosyne 的全部私有性依赖 CI-1.9 的账户隔离，而 CI-1.9 从几轮前就停在 **READY / 0 通过**，等一个授权。

也就是说：**我们在设计第三层，而第一层一条验收都没跑。**

这不是排期问题，是**风险偏好问题**——设计是安全的，执行是有后果的。十二轮下来，我们（包括我）一直待在那个安全的房间里，用"还有议题没定"作为不进入执行的合法理由。

外部审查者会说得很直接：**"你们的记忆系统卡在一个未授权的建号操作上。先去做那个，别再加规则了。"**

### 12.4 如果只让我给一条建议

> **两周内，用现有的 ACL 隔离，给 Hermes 一个 append-only 的 journal 目录，写三十条真实记录，然后读一遍。**
>
> 不要 schema，不要权限矩阵，不要删除流程。就是文件。
>
> 读完你会知道哪些规则是真的需要的——我猜是零到两条，而不是三十三条。

理由：**这个设计之所以长到 102 KB，是因为它从没接触过现实。** 每一轮讨论都在用思想实验生成新规则，而规则写起来便宜、住进去很贵。唯一能治这个的办法不是更聪明的设计，是**让它先跑起来**，让现实来删规则。

### 12.5 我的偏见，必须披露

我不是独立审查者，我是设计者。这个身份会让我的判断偏向两个方向，你们读的时候要打折：

1. **倾向于"重构"而不是"废弃"**——因为废弃等于承认我十二轮的工作白做。我在 §7 给的"小得多的系统"，可能仍然比真正需要的更大，因为我不想把自己写的东西全扔掉。
2. **倾向于"再多定一个规则就安全了"**——这是我这一路最稳定的错误模式。

所以如果你们中间有人读完说"干脆别做记忆系统了，就让她写日记"，**那个判断可能比我的更准**。我不会反驳它。
