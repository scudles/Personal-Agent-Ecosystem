## 2. Observer 五条收尾要求：逐条核对

| # | 要求 | 落点 | 判定 |
| --- | --- | --- | --- |
| 1 | 预算限制同时生效，不允许互相抵消 | `SECURITY.md` §13 + `MVP` §4.1 | **已满足**：判定式为 `est ≤ min(单次, 日剩余, 月剩余, 池剩余, scope per_run)`；明确禁止用余额抵扣单次上限 |
| 2 | 区分本地预算估算与 Provider 硬限制 | `SECURITY.md` §14 + `MVP` §9 | **已满足**：本地＝软限额+硬停止；Provider 硬边界只有余额与周窗口；禁用「provider 保证不超过 X」的表述 |
| 3 | 六项剩余风险有记录和缓解措施 | `THREAT_MODEL.md` §6 | **已满足**：R1–R6 每条四列（风险/缓解/残余/何时消除）；并写明「决策已定 ≠ 控制已实现」 |
| 4 | 审计不能被 Agent 自行修改或删除 | `SECURITY.md` §10 + `MVP` §5.1 | **部分满足（诚实口径）**：四道约束（单一写入者/只追加 ACL/哈希链+checkpoint/外部镜像）能挡住改行与常规删除；**同账号下只能「发现删除」，不能「阻止删除」**，阶段 B 后才真正生效 |
| 5 | 路径穿越 / UNC / 符号链接逃逸 | `SECURITY.md` §11 + `MVP` §4.2 | **已满足（设计）**：规范化流程 + 6 条验收用例 P1–P6，实现时必须逐条过 |

> 第 4 条我标「部分满足」而不是「已满足」，因为把检测能力说成防护能力会直接误导后续决策。这是本轮我唯一没有按"要求即达成"表述的地方。

## 3. 六项接受风险的记录与缓解（摘要）

完整表见 [THREAT_MODEL.md](../THREAT_MODEL.md) §6。摘要：

| 风险 | 现在的缓解 | 残余 | 消除条件 |
| --- | --- | --- | --- |
| R1 同账号互读 | scope 不给隐私目录 + 工具白名单 + 异常路径告警 | 有 shell 就能绕 | 阶段 B |
| R2 出站只能观察 | host 白名单 + 工具允许表 + 审计 host | 不能阻断 HTTPS | 阶段 C |
| R3 插件风险 | 插件白名单 + 低权任务隔离 + 优先 Linux 侧 | 插件拥有宿主权限 | 阶段 C / 换环境 |
| R4 提示注入 | scope 限损 + 高危动作 `per_use` | 语义诱导无法自动识别 | 永久残余 |
| R5 桌面可读实例数据 | 刻意设计 + 审计记录 | 无强制隔离 | 不消除 |
| R6 审计只能检测篡改 | 哈希链 + checkpoint + 外部镜像 | 可被整文件删除 | 阶段 B |

## 4. 基线里明确「没有做」的部分（避免被误读为已交付）

- 没有 `policy/agents.yaml`（连空文件都没有）；没有校验器；没有 `decide()` 实现。
- 没有任何 SQLite 表；没有账本；没有审计文件。
- 没有创建 `pae-*` 账号；没有改 ACL；没有跑 Phase 1.7 的任何一项。
- 没有让任何 Agent 获得任何新权限；权限当前状态仍为 **零**。
- 没有做第一次真实模型任务。

## 5. 下一阶段的授权点（按依赖排序）

1. **授权写 `policy/agents.yaml`（epoch 0）+ 只读校验器**：纯本地、零新依赖、不启用、不给任何 Agent 权限；产出是「能校验、能报错」的文件与脚本。
2. **授权实现账本 + 审计（空跑）**：不接 ACP，只用测试数据跑 12 条验收。
3. **授权 Phase 1.7 的 A 阶段部分**（应用层 ACL 之外的只读检查，仍不建账号）。
4. **授权创建 `pae-*` 账号与 ACL PoC**：这一步会改动系统，必须单独批准，且按迁移报告 M1–M8 执行、先备份 ACL。
5. **授权第一次真实模型任务**：需要预算生效 + 一次 `per_use` 批准单。

每一条都需要单独点头，不能一次批"全做"。
